## The problem this solves

The normal entry today enumerates the grammar and certifies every candidate. In
the 2026-09-12 run that was 144 candidates per task and **377 seconds**, against
a 9.92-second workload. The evaluated quantity `q` was known from the start, and
almost all of that work was spent on candidates that could not possibly serve it
— 125 of 144 were refused on the observable check alone.

When `q` is given, the closure it needs can be constructed from `q` instead of
searched for.

## The construction

With `K_g f = f ∘ T_g` the pullback of the generator action,

```
V0     = span{q}
V_{k+1} = V_k + Σ_g K_g V_k
```

iterated to a fixed point gives `V*`, the smallest generator-invariant linear
space containing `q`. Any other generator-invariant space `W` from which `q` can
be recovered linearly contains `V*`.

Reference implementation to consult: **CLUE, Algorithm 2** — the minimal common
invariant subspace containing a given row space. Only that algorithm is needed;
the ODE machinery around it is not. **Confirm the algorithm's stated
preconditions against the source and against this setting before relying on
it** — the handoff's literature table records that CLUE has not been retrieved.

## What to do

1. **Read `discover_action_observable_basis` first**
   (`math_os_prototype/finite_generator_problem_dna.py`). It already performs
   this closure. The work is to call it from the task's quantity, generally —
   not to write a second closure.

2. **Add a direct route** that takes `TaskSpec.observable_expression` and
   returns the closure, the action matrices and the read-out. Wire it into
   `self_directed_search.solve` as a route alongside the existing one.

3. **Do not embed `c1`, `c1 + c2`, any basis, or any final answer.** The
   expression comes from the task. The basis, the auxiliary quantities, the
   matrices and the read-out coefficients are computed.

4. **Keep every condition that is checked today.** Transition, evaluated
   quantity, legality, goal, start state, and the multiplicity of the counting
   DP. The direct closure is minimal among *linear* invariant spaces containing
   `q`; that is not the same as preserving legality. A task whose legality the
   `q`-closure does not preserve must not use it — fall back to an existing
   exact route if one applies, and otherwise stop as unmet.

5. **Minimal ≠ fastest.** Minimality is a statement about the linear space, not
   about wall time. A change of basis inside the same space, or a different
   method, is an optional optimisation and must be measured, not assumed.

6. **Keep the 144-candidate route.** It stays available for comparison and for
   open-ended observable search. It stops being a mandatory stage of a normal
   answer when `q` is supplied.

## Reuse

Search the ledger before constructing anything, keyed on the combination of
action, coefficient field, domain and observable. When only the **initial state**
or the **word length** changes, and the change stays inside the certificate's
proved range, reuse the stored basis, matrices and proof: update only the
initial vector and whatever follows from it.

For several quantities at once, build the closure from the span of all of them.
Two candidates whose bases span the same space are one representation — use
`representation_certificate.same_span`, which decides this by exact rank.

## Cost accounting

Keep these three apart, as `docs/handoff/MORTRA-20260912.md` §6.1 does:

- **A** — an existing route named from the start, run on its own.
- **B** — the whole automatic answer, including candidate generation,
  certification and selection. If 144 candidates were acquired and the existing
  route was then chosen, that cost belongs here and the run was *not* free.
- **C** — reuse of an already-stored representation.

Once a representation is acquired, do **not** re-charge its acquisition on every
later use. The decision before acquiring and the decision after are different
decisions.

## How to compare it

From the normal entry, with the configuration fixed before the run, over the
same four tasks (`axis1`, `c1-plus-c2`, `axis1-from-AG`,
`axis1-collision-free`):

- the existing 144-candidate route
- the direct closure from `q`
- the existing exact route (concrete-state merge)

Check the direct closure's basis and matrices by the identity and the read-out.
Compare maximum, count and the whole distribution against independent
enumeration at small n; compute long n from the certified representation only.
For the task with a different initial state, and for a different n, confirm the
stored representation was read and **not** re-acquired.

No candidate, answer or auxiliary quantity is supplied by hand during a test. A
defect means going back to development and running again as a new run.

## Reporting

Give acquisition cost, answer cost, reuse cost, the space obtained, and the
actual answers. Record observed general formulas as **conjectures** — agreement
at a few lengths is not a theorem for all n. Observable search for new
mathematics stays available as a separate activity from the answering route.

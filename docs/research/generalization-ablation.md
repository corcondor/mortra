## certified の列だけ見てはいけない

**A1 は正答 10 に対して誤答 12。正しく解いた数より間違った数が多かった。**
6.0% という数字だけでは分からない。

A2 で誤答 12 → 0。timeout 2 → 0、parse_failed 3 → 0。

## 途中で自分の数字を潰した記録

一度 A2 で 36 問（21.6%）と出た。中身を見たら偽陽性だった。

```
log(r) = (1 < α ∧ 1 < r ∧ …)   目標と違う変数の解領域を返していた
α = a_1                          前提 a₁ = α を α について解いただけ
e  = 0 < t < ∞                   e を変数として解いていた
Sum(a_k, (k,1,n)) = a_k·n        束縛変数が添字に残ったまま和を取っていた
p_n = p_n / f(x) = f(x)          何も計算していない
```

番人（`is_trivial` / `restates_premise` / `usable_goal` / 不等式の目標一致）を入れた結果、
**36 のうち 26 が偽陽性として落ちた。** A2 の真の値は 10。

多候補探索（目標を1つに決め打ちせず全候補を試す）も入れたが、
番人を通すと 13/60 = 21.7% で、決め打ちの 21.6% と変わらなかった。
**上がったように見えたのは全部偽陽性だった。**

## 実際に効いたもの — 本文を読むこと

167 問中 **78 問（47%）には印字された等式が一本も無い**。条件は日本語の本文にある。

収集器が `<math>` を `⟦式⟧` に置き換えているので、
本文中の `⟦式⟧` の個数と式の添字が一対一に対応する。これを使う。

```
「⟦式⟧ の範囲を求めよ」  →  直前の ⟦式⟧ が目標
「⟦式⟧ を自然数とする」  →  その式に x > 0 を課す
```

**式だけを見て「最後の非関係式」を目標にしていたのが、点を落としていた最大の原因。**
どれが問われているかは本文が言っている。

```
A2 → A3b   +29 問、誤答 0 のまま
```

## 一般演算あたりの効き

```
A0→A1    MathML を保持              +10 問（ただし誤答 12）
A1→A2    AST と役割解決             誤答 12→0、偽陽性 26 を除去
A2→A3b   本文の指示と条件            +29 問、誤答 0
問題別のパッチ                       0 件
```

一つの一般的な変更が 167 問に波及した。例外分岐は足していない。

## A3（意味核・番人）が certified を上げなかったこと

**上げていない。Δ +0。**

効いたのは別の軸だった。

- 偽陽性 26 件を除去した（A2 の見かけ 36 → 真の 10）
- 誤答を 12 → 0 にした
- `proved` の定義が 7 箇所にあったのを一つにし、横断して数えられるようになった

**正答率には効いていない。** その事実をそのまま出す。

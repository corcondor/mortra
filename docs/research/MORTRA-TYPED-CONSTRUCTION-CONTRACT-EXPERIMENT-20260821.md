# MORTRA 型付き補助構成逆合成実験

日付: 2026-08-21

## 目的

既存の証明済み能力 51/89 を保持したまま、残る38問について、未解決の
型付き証明義務から補助構成を逆向きに合成すると追加のネイティブ証明書を
得られるかを検証する。

## 原理

Newclid/Yuclid の定理を Horn hyperedge、構成定義を型付き射として扱う。
未解決義務に点の穴がある場合だけ、構成のpostconditionと逆単一化する。

例:

```text
coll(?X, A, B)       -> on_line(A, B) -> X
cyclic(?X, A, B, C) -> on_circum(A, B, C) -> X
```

穴のない `cyclic(P,A,B,C)` は証明すべき命題であり、新しい点の構成へ直接
変換しない。候補は提案にすぎず、得点化にはYuclidによる終端証明書の再生を
必須とする。

この方針は、AlphaGeometryの「記号推論の行き詰まりから補助構成を提案する」
構成、FormalGeoの前向き・後向き探索、GenesisGeoの証明依存グラフから必要な
補助構成を抽出する実装に対応する。MORTRAでは外部LLMを使わず、有限の構成
契約と型付き単一化で候補を生成する。

一次資料:

- [AlphaGeometry](https://deepmind.google/blog/alphageometry-an-olympiad-level-ai-system-for-geometry/)
- [AlphaGeometry 2](https://deepmind.google/blog/ai-solves-imo-problems-at-silver-medal-level/)
- [GenesisGeo official repository](https://github.com/ZJUVAI/GenesisGeo)
- [FormalGeo official repository](https://github.com/FormalGeo/FormalGeo)
- [HAGeo paper](https://arxiv.org/abs/2512.00097)

## 方法

1. HAGeo-409の固定held-out 89問から、ネイティブ証明書の集合和で既に解けた
   51問を除く。
2. 残る38問を、データセットの補助構成を除去してYuclidで再実行する。
3. 現在の事実から後向き証明義務を作り、点の穴を含む義務を抽出する。
4. JGEX構成定義のrelation atomsと逆単一化し、既存点だけを入力とする有限候補
   を生成する。
5. 候補を一つずつ問題へ追加し、Yuclid再実行で閉じた親義務と新しい残差を測る。
6. 最終goalが閉じた場合だけ、証明ハッシュを持つ追加正答として51問の集合へ加える。

問題名、既知解、データセットの補助点、期待される構成列は候補生成に使わない。

## 結果

### 全38問の構造監査

成果物: `data/hageo-unresolved-contract-audit-2026-08-21.json`

- 残り: 38問
- witness穴を持つ問題: 26問
- 従来の予算付き列挙で直接候補を保持した問題: 12問
- 逆合成で候補を得た問題: 25問
- 従来列挙に無い候補を得た問題: 25問
- 再実行時のネイティブ正答: 0問

したがって、主要な欠落の一つは構成語彙そのものではなく、高アリティまたは
特定束縛の候補が一般列挙の上限外へ落ちることだった。

同一のseed、候補予算、Yuclid feedbackで比較した。

| 条件 | 選択した3構成 | 閉じた親義務 |
|---|---|---:|
| control | mirror, midpoint, midpoint | 0, 0, 0 |
| typed contract | midpoint, mirror, midpoint | 2, 1, 1 |

両条件とも最終goalは未証明だった。したがって、逆合成は局所的な証明進捗を

### 固定25問: N=1, K=1

- 完走: 25/25
- timeout / execution error: 0 / 0
- 追加正答: 0/25

### 深さ実験: 2023SAGFp8, N=6, K=2

- 完走軌道: 2
- 追加正答: 0
- 軌道0の閉じた親義務: 2, 1, 1, 1, 1, 0
- 軌道1の閉じた親義務: 2, 1, 0, 0, 0, 0
- MORTRA総合証明済み集合: 51/89を維持

### AND枝整合性と親状態からの増分構築

初期実装は `perp(?C,?D,A,B)` と `para(?C,?D,P,Q)` を平坦な二つの需要として
扱っていた。この場合、別々の候補が異なる `?C,?D` を代入しても二条件を閉じた
ように見える。これはAND枝として不正である。

そこで次を実装した。

- 同一枝の全atomに一つの置換を共有する `consistent_branch_closure_score`
- 構成postconditionで閉じたatomを除き、同じ置換を残余atomへ適用する
  `reduce_obligation_branches`
- 地上残差を有限深さの証明DAGで再分解できたときだけ次の構成へ進む制御
- 計画した枝を一つも縮約しない候補の軌道棄却

固定5問、N=3、K=1では全5問が各ラウンドで同じ枝を縮約したが、追加正答は0。
成果物は
`data/contract-portfolio-causal-low-witness5-n3-k1-f4-2026-08-21.json`。
以前の `on_pline -> on_pline -> on_pline` 型の独立な局所一致は、例えば
`on_pline -> intersection_lp -> mirror` の束縛付き補題経路へ変化した。

### 深さと資源の反証実験: 2007CMOp4

深さ8、4軌道、各段4候補を無制限に並列化すると、多数のYuclidプロセスが同時に
起動しメモリを圧迫したため中止した。これを受け、全軌道で共有する
`max_verification_concurrency` を実装した。

資源上限2でN=6、K=2を再実行した結果:

- 完了: 2軌道
- 一意な経路: 2
- 追加正答: 0
- 壁時計時間: 486.78秒
- 軌道別時間: 280.48秒、485.33秒
- 最終ネイティブ残差: いずれも14 relation demands

成果物:
`data/contract-causal-staged-2007cmop4-n6-k2-f2-2026-08-21.json`

深さ3から6へ増やしてもこの固定例では終端証明を得なかった。したがって、現状の
候補集合に対して深さだけを増やせば得点が上がるという仮説は支持されない。

### 終端厳密専門器の接続

構成済みJGEX問題を別プロセスの厳密消去器へ渡す
`run_jgex_exact_specialist.py` を追加した。`goal_local_relational` 表現で目標に関係する
構成節を切り出し、local eliminationとGroebner再生を行う。時間上限は軌道ごとに
設定し、`exact_replay=true` の証明書だけをMORTRA全体の正答へ加える。

2007CMOp4、N=1、K=1、終端専門器60秒の接続試験では、配線とプロセス終了は正常、
結果は `right_censored_timeout` だった。したがって追加正答には数えていない。
成果物:
`data/contract-exact-terminal-v2-2007cmop4-n1-k1-f2-2026-08-21.json`

## 考察

逆合成は候補供給の欠落を改善した。しかし、局所義務を閉じる候補を連鎖しても
終端定理には到達しなかった。したがって現在の主要ボトルネックは次の二つに
分離できる。

1. 一段の後向き展開でwitness穴が現れない12問について、目標条件付き証明基底
   上でAND/OR分岐を保った多段分解が必要。
2. 局所的に閉じた義務を、同じ証明枝の中で中間補題へ束ねる必要がある。
3. 構成後に残る `aequation / cyclic / npara / cong` などの地上義務を、
   Wu/Gröbner/MMT専門器へ渡し、証明書付き事実として同じ枝へ戻す必要がある。
   終端JGEX厳密消去器への配線は完了したが、固定難問では60秒で時間打切りとなった。

単に探索深さや候補数を増やすだけでは、別のOR枝の局所進捗を混ぜる危険がある。
次段では枝IDを保存したまま、`構成 -> 新事実 -> 中間補題 -> goal` の同一枝上の
進捗を評価する。

## 結論

型付き補助構成の逆合成は実装され、従来列挙から脱落していた候補を25/38問で
復元し、固定例では対照より多くの証明義務を閉じた。一方、追加の終端証明はまだ
0であり、総合得点は51/89のままである。AND枝の一貫した束縛、親状態からの
増分残差、無関係候補の棄却、検証並列数の上限までは実装・再測定できた。
次の実験対象は、具体化された地上残差を既存の厳密専門器へ接続し、再生可能な
証明書が得られた場合だけ総合集合へ加える証明書交換である。

## 追試: 記号証明器ポートフォリオ

上記の次段を実装し、GCLC/Wuを共通の真理面へ接続した。固定未解決38問で
`2007CMOp4` と `2021CGMOp7` の証明書を得た。問題名による集合和で重複を除くと、
総合証明済み集合は **51/89から53/89** へ増加した。

Area法は同じ38問で追加正答0だった。翻訳未対応だった8問の構成語彙も原始構成へ
展開したが、追加正答は0だった。したがって、次の課題は語彙数や探索深さではなく、
巨大な一括消去を型付き中間補題へ分割して証明器間で交換することである。

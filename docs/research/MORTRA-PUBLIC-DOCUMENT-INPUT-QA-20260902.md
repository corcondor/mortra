# MORTRA 公開入力・作図・解答生成の検証（2026-09-02）

## 結論

公開画面と同じ構成のローカル環境で、文字入力、画像、PDF、二問融合を実行した。簡単な方程式、画像から読み取った直角三角形、PDFから読み取った積分不等式、二次形式と期待値の融合は、問題文、厳密な答え、証明、図、検証証明書まで生成できた。

三次曲線と単位円から有理角六角形を扱う難問は未解決である。正四面体に含まれる立方体の問題は、初回試験では未解決だったが、三次元包含の厳密解答経路を追加した後の公開画面で解決した。文字認識の成功と数学的な解決を分け、未解決問題は正答数へ含めていない。

## 目的

`mortra.ai` の入力欄が、手入力だけでなく画像とPDFを受け取り、MORTRA自身の計算経路で次の成果物を返せるかを確かめる。

1. 元の数学的条件を保った問題文
2. 問いに対応する厳密な答え
3. 一手ずつ読める証明
4. 証明に対応する図または関数のグラフ
5. 結論を再検査できる証明書

外部の大規模言語モデルは、文字認識、解法探索、証明生成のいずれにも使用していない。画像とPDFの文字認識は、利用者のブラウザー内で動く日本語・英語の文字認識器と数式認識器を使用した。

## 方法

入力形式と難易度を変えた六つの事例を、公開画面と同じ操作で実行した。成功の条件は、画面が更新されたことではない。要求された答えと証明書が揃った場合だけ、数学的に解決したと判定した。

文字認識では、本文と数式を別々に認識してから位置関係に従って再構成した。信頼度が低い数式候補は自動採用せず、本文の認識結果を残して利用者へ確認を求める。PDFが複数ページの場合は、一つの問題入力として先頭ページだけを読み、読取範囲を画面に表示する。

## 発見した不具合と修正

三次曲線の難問では、問題文中の「正の整数 q」という制約が先に見つかったため、探索の出発構造が整数構造になっていた。三次曲線、単位円、六角形という主対象より、付随する整数条件が優先されていたことが原因である。

意味解析で検出した構造を、主対象と制約に分けた。現在は、三次曲線の問題を `CubicPolynomialMap` から開始し、整数条件を後から適用する。問題番号や固有の数値による分岐は追加していない。同じ修正は、曲線と整数条件を併記する他の問題にも適用される。

また、停止ボタンと初期化ボタンが以前の長時間処理を画面へ再接続する場合があった。処理識別子とURLを同時に消すように修正した。

## 考察

画像やPDFを読み取れるだけでは、MORTRAが問題を解けることにはならない。今回の試験では、入力の再現、型付き構造への変換、解答、図、証明書を別々に確認した。この分離により、三次曲線の問題は「認識成功、意味解析の優先順位を修正、証明未完了」と正確に記録できる。

二次形式と期待値の融合では、二次形式を対称行列へ変換し、確率変数の二次モーメント行列と縮約して `E[q(X,Y)]=tr(AM)` を計算した。同じ合成から係数とモーメントを変えた三問を生成し、すべてを再計算して検証した。これは問題文を言い換えただけではなく、一つの再利用可能な数学構造から複数の問題を作った事例である。

## 残る課題

三次曲線と単位円の難問は、探索の出発点を修正した後に本番ワーカーで再実行する必要がある。正四面体問題で追加した三次元包含経路については、他の多面体の組合せを固定未見集合として試し、適用範囲を測る必要がある。

画像の初回読取では約200 MBの認識モデルを利用時に取得するため、最初の一回だけ待ち時間が長い。通常のページ表示にはモデルを含めず、画像またはPDFを選んだ時点で読み込む設計にしている。

本番試験でも文字認識の初期化とPDF処理に数分を要した。今回は処理時間を自動計測していないため、正確な秒数は主張しない。次回はモデル取得、画像前処理、本文認識、数式認識を別々に計測する必要がある。

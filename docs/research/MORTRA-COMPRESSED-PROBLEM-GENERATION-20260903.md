# MORTRA 構造縮約・公開入力回帰試験（2026-09-03）

## 目的

問題番号、固有の数値、表層文型を覚えず、少数の実行核を異なる入力構造と問いへ再利用して、問題文・厳密解答・証明経路・説明図を生成できるかを測る。

また、局所の実行核で解ける入力が `mortra.ai` の公開画面では失敗していた分断を特定し、同じ経路へ接続する。

## 原理

生成構造を次の三層に分ける。

1. **実行核**: 有限作用、終結式、二次形式、格子計数など、係数や変数名に依存しない計算原理。
2. **型付き入力プログラム**: 親問題から抽出した対象、制約、作用、観測量。
3. **問い**: 和、積、差、期待値、周期、個数など、証明すべき量。

この分離により、係数変更や変数名変更を新しい解法として登録せず、同じ実行核へ送る。解法の再利用可能性は、問題文の一致ではなく、正規化後の実行核・入力プログラム・問いの指紋で判定する。

## 方法

### 1. 共通実行核

- 有限軌道の列挙、約数列挙、最小周期、周期開始点を `finite-generated-action` に統合した。
- 三角関数の有限軌道と Pell 型漸化式の合同軌道を、この共通核から実行するよう変更した。
- 公開生成器と実験器が同じ生成器一覧を参照するよう、実行時登録表を一つにした。

### 2. 構造正規形

- 問題 ID、数値、変数名を構造指紋から除外した。
- 実行核、入力プログラム、問いを別々に数えた。
- 係数変更試験と変数名変更試験を行った。

### 3. 未見入力試験

14件の構造入力から、次の6実行核を試した。

- 多項式の根集合
- 二次形式と期待値
- 漸化式と合同軌道
- 格子多角形と Pick の定理
- 整数辺三角形と内接円・外接円
- 一次方程式

### 4. 公開入力の分断診断

公開画面へ通常の日本語で `実数 t が 17t+5=158 を満たすとき、t を求めよ。` と入力した。修正前は、明示的な TeX 区切りがないため式が直接厳密解法へ渡らず、誤った候補 `158` の後に長時間処理へ移った。

通常文中の数式区間を決定的に抽出し、`変数を求めよ` を方程式の問いとして認識するよう修正した。解答には、式の抽出、零への正規化、厳密求解、元の式への代入確認を証明プログラムとして残す。

### 具体例

二次形式と期待値の二親入力から3問を生成し、厳密値 `39`、`75`、`60` を得た。全問に射の列、説明図、独立検算を付けた。

三次式 `x^3-x-3` と二次式 `x^2-2x-2` の根集合から、和・積・差を根にもつ三つの多項式を生成した。終結式による生成と独立した根の照合が一致した。

一次方程式の公開入力回帰では、修正後に `t=9` を返し、元の式への代入残差は0だった。登録済み問題への照合ではなく、現在の入力から証明プログラムを合成した。

## 考察

今回の縮約は、三角関数と漸化式を同じ問題として扱ったものではない。両者の入力プログラムと問いは異なるが、有限集合上の作用、軌道、周期を扱う実行核を共有できた。この境界を保つことで、問題固有の表現を増やさずに再利用範囲を広げられる。

公開画面の失敗原因は数学核の不足ではなく、通常文から厳密解法へ数式を渡す接続不良だった。局所核だけを評価しても製品能力は保証できないため、公開画面からの回帰試験を必須にする。

## 結論

問題固有の ID、係数、変数名を使わず、6実行核から55件の検証済み問題を生成できた。係数変更と変数名変更にも構造どおり応答したため、少なくとも今回の試験範囲では表層暗記ではない。

さらに、通常の日本語で書いた一次方程式を公開解答経路へ渡せない欠陥を修正した。次の判定は配備後の `mortra.ai` で、簡単な一問、二次形式と期待値、根集合の融合、図を要する幾何を直接入力し、表示・文字・図・解答・再開状態を確認して行う。

## 追試: 問い代数の直接出力と公開キュー

### 目的

問題文を作った後から文字列で種類を推測する方式では、問題固有の言い回しを記憶している可能性を排除できない。そこで、各生成器が問題文とは別に、問いを構成する型付き操作列を直接出力するようにした。公開候補も問題番号や係数ではなく、この操作列の指紋で重複を除く。

### 方法

問いを作る操作を、`transport`、`pair`、`map`、`fold`、`equalizer`、`preimage`、`period`、`extremum`、`boundary`、`eliminate`、`normalize`、`contract` の12種類に限定した。入力構造を作る射の列と、そこから何を問うかを作る射の列は分離した。

現行の6生成器は、問題文に依存せず型付き操作列を直接返す。旧生成物のように問題文から操作列を後付け推定したカードは、検証済みでも公開キューには入れない。公開可能とする条件は、直接出力、厳密解法、独立検算、全親入力への依存、未登録合成、問題文・図・解答の完備である。

未登録の既約三次式68個から異なる2式を選ぶ2,278組について、根の差・和・積を問う候補を全列挙した。係数変更では答えが変わり、問いの操作列は変わらないことも検査した。

### 結果

| 項目 | 結果 |
| --- | ---: |
| 現行生成器の試験入力 | 14件 |
| 現行生成カード | 55件 |
| 問い代数を直接出力 | 55/55 |
| 後付け推定 | 0/55 |
| 相異なる問い代数 | 6 |
| 使用した共通操作 | 7種類 |
| 三次式の親ペア | 2,278組 |
| 新規に厳密生成・検証した候補 | 3,468件 |
| 公開条件を満たした候補 | 2,512件 |
| 係数変更で答えが変化 | 通過 |
| 係数変更で問い代数を保存 | 通過 |
| 公開キューへの入力 | 56件 |
| 公開条件を満たした入力 | 35件 |
| 問い代数の重複を除いた採用 | 5件 |
| 採用5件で使う共通操作 | 7種類 |

旧実験の58カードと54カードはすべて後付け推定だったため、公開対象から除外した。数値上の成功を取り消したのではなく、「生成器自身が問いの構造を出した」という今回の主張には使わないという区別である。

最初の公開候補は、`f(x)=x^3+x+1` と `g(x)=x^3+2x-2` の根をそれぞれ `α,β` とし、相異なる `α-β` を根にもつ最高次係数1の多項式を求める問題である。問い代数は `pair -> map -> eliminate -> normalize` で、得られた答えは

`z^9+9z^7+9z^6+21z^5+18z^4-12z^3+9z^2-25z+31`

となった。終結式、平方因子除去、全根の独立照合、両親式の摂動試験を通過した。

### 考察

3,468件の候補が一つの問い代数を共有し、係数を変えると答えだけが変わった。したがって、この系列は係数や完成済み問題文の暗記ではなく、同じ4操作の合成から生成されている。さらに、分野の異なる5件をわずか7種類の操作で公開キューへ選べたため、問題ごとの表現を増やさずに表面と数学構造の両方を変えられることが確認できた。

ただし、これは現在接続済みの代数・数論・確率・格子幾何の範囲に対する結果である。任意の数学分野について十分とはまだ言えない。次は、新しい生成器にも同じ直接出力規約を課し、後付け推定経路を段階的に廃止する。

### 結論

問題固有の表現を公開単位にする方式から、少数の型付き操作の合成を公開単位にする方式へ変更した。現行経路では55/55カードが直接出力であり、新規探索では3,468件すべてを同一の共通操作列から厳密生成できた。公開用の5問は問い代数が互いに異なり、同じ問題の係数違いを水増ししていない。

XおよびInstagram用の問題画像・解答画像・本文は生成済みである。投稿処理は公式アカウント以外を拒否するようにし、現在の認証情報が公式アカウントへ接続された時点で実行する。

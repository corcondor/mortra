# MORTRA 終端信用の凍結転移実験

## 目的

終端の厳密証明から中間構成へ戻した信用が、同一問題内だけでなく、別の未解決問題の補助構成探索へ
転移して得点を上げるかを検証する。同じ問題を見ながら調整することを避けるため、開発問題で作った
信用表を保存し、評価中は更新しない。

## 仮説

1. 点名、問題名、数値座標を除いた構成射の型は、別問題でも一致する。
2. 証明書付き信用で必要構成を候補幅の内側へ移せば、Pass@Kが上がる。
3. 真偽判定をYuclid native証明再生に固定すれば、誤証明は増えない。

## 原理

最初の完全一致署名は、17個の構造量と全目標述語の一致を要求した。この署名は安全だが、固定未解決
5問の全12ラウンドで一致候補が0となり、別問題へ転移しなかった。

そこで、型付き忘却写像を3段にした。

```text
完全署名(family, input role, equality, target, shape)
  -> 目標文脈(family, input role, equality, target)      weight 0.50
  -> 射の型(family, input role, equality)                weight 0.25
```

粗い像ほど信用を弱める。順位は変えてよいが、定理の受理条件は変えない。未証明trajectoryからは信用を
発生させず、評価集合から信用表を更新しない。

## 方法

### 開発

- 開発問題: `2011CTSTp16`, `2017G3`, `2016CGMOp7`
- native証明依存から得た事象: 9
- 完全署名: 6
- 階層信用表のentry: 17
- 禁止入力: 問題ID、期待解、点名、数値座標、dataset補助構成

### 評価

対照は `residual-feedback`、処置は同じ探索器へ凍結信用表だけを加えた `terminal-credit` とした。
seed、候補文法、候補数、Yuclid、時間制限は同じである。

1. calibration 5問: N=3, K=1, feedback=1, 180秒/問
2. frozen probe 10問: N=1, K=1, feedback=1, 90秒/問

calibrationを見て完全一致から階層署名へ変更したため、5問は最終held-outとして数えない。階層署名を
固定した後の10問では追加調整をしていない。timeoutは誤答でなく右打切りとして分離した。

## 結果

### Calibration 5問

- 完全観測: 3問、右打切り: 各条件2問
- 正答: 対照0、信用0
- 信用候補13、順位上昇8、経路変更3、最大16位上昇

### Frozen probe 10問

| 指標 | 対照 | 凍結信用 |
|---|---:|---:|
| 完全観測 | 9 | 9 |
| 右打切り | 1 | 1 |
| 正答 | 0 | 0 |
| 実行エラー | 0 | 0 |
| 平均attempt時間 | 10.57秒 | 11.16秒 |

信用群では25候補に信用が届き、22候補が上昇し、9問中8問で経路が変わった。最大上昇は20位だった。
信用表の事象数は評価前後とも9であり、評価問題からの更新は0である。誤証明も0だった。時間は
平均5.63%増えた。

## 考察

仮説1と3は支持された。信用は別問題へ到達し、実際に探索経路を変えた。また、正しさの境界は崩れて
いない。

仮説2は支持されなかった。候補順位を大きく変えても追加正答は0だった。粗い射では`foot`が多くの
問題で上位へ集まり、局所的に成功頻度の高い構成を優先するだけでは、問題固有の中間補題を発明できない
ことが分かった。これは「解法暗記」ではないが、「頻出射への崩壊」であり、汎化成功とも呼べない。

今回の結果から、次に必要なのは正の終端信用を増やすことではない。次の候補は、信用候補を1本だけ
探索枠へ予約し、残りを現在の証明残差で比較する混合制御である。評価は別の固定集合で行い、
`credit-only`、`residual-only`、`one-credit-plus-residual`を比較する必要がある。

## 結論

終端信用の問題間転移と凍結評価は実装できた。しかし、10問の固定probeではPass@Kの改善も高速化も
得られなかった。したがって、この機構を得点向上として採用してはいけない。成果は、転移不能の原因を
過細な署名と特定して解消し、その次に粗い信用だけでは補助構成発明にならないことを反証した点にある。

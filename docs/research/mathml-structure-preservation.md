# 構造を保つと数学能力が上がる

同一問題 167 問・同一 CAS・同一判定で、**入力の表現の扱い方だけ**を変えた。

```
平文化（タグを剥ぐ）      certified  0/167 =  0.0%
文字列で復元（正規表現）   certified 10/167 =  6.0%   誤答 12
木として保持（AST）        certified 36/167 = 21.6%   誤答  1
```

## 何が消えていたか

```
剥いだ後   log x x - 1
MathML    log x <= x - 1

剥いだ後   lim n n 1 2 log(1+x 1 n 2) dx
MathML    Limit(n*Integral(log((1+x**(1/n))/2), (x, 1, 2)), n, oo)
```

不等号も積分区間も消えていた。**意味を運んでいたのはタグの方だった。**

## 文字列経由が誤答を生む

A1（文字列で復元）は正答 10 に対して**誤答 12**。正しく解いた数より間違った数のほうが多い。
6.0% という数字だけでは気づけない。

木から直接読むと誤答 12 → 1、timeout 2 → 0、parse_failed 3 → 0。

## 積み上げた正規表現の副作用

個別パッチで潰していた事故は、すべて文字列経由が原因だった。

| 事故 | 原因 |
|---|---|
| `\b` がバックスペース(0x08) | 非raw文字列。3回埋まり、静かに間違った結果を出した |
| `I(a,n)` が虚数単位に化けた | 記号の役割が構造ではなく辞書で決まっていた |
| `sin(n*x)*` の末尾の `*` | 見えない乗算が文字列に残った |
| `(a,b)` でタプル例外 | 型が無いまま sympy に渡していた |

**個別に直すのをやめ、木を木のまま扱う経路に置き換えた。**
制御文字は不変条件にした（`scripts/control_char_invariant.py`、220ファイル 0件）。

## 仮説の検証

> 表現をよく理解すること自体が、最終的な問題解答能力を上げる

問題別のパッチは 0 件。一般的な変更が 167 問に波及した。**仮説どおり。**

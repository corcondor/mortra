# MORTRA 難問生成実験

## 目的

MORTRA が、親問題の数値や問いを置き換えるだけではなく、異なる数学構造を合成した問題を生成できるかを確かめる。生成後は、問題文だけでなく、厳密な答え、読者が追える解答、独立した検算、親問題への依存関係まで検査する。

## 仮説

1. 型が適合する二つの証明経路を途中で合成すれば、親問題の単純な逆再生ではない問題を生成できる。
2. 証明段数だけでは難しさを測れない。長い周期の列挙は手数が多くても、本質的に難しいとは限らない。
3. 有限個の直接計算と、その後の一括評価を分ければ、厳密さを保ったまま解答を短くできる。

## 方法

`全問題.tex` から抽出した90問について、相異なる二問の全4,005組を調べた。今回は、親問題の検証済み解答を同じ形式へ写した候補を除き、親問題から抽出した数学構造を直接合成した候補だけを対象とした。

各候補について、次の量を別々に記録した。

1. 証明に必要な段階の数
2. 証明中で使う異なる表現変換の数
3. 親問題と90問全体に対する問題文の三文字列一致率
4. 二つの親問題がともに必要か
5. 二つの親問題から来た証明経路が途中で合流しているか
6. 未使用の条件が残っていないか
7. 同じ答えを別の計算方法で再生できるか

これらを一つの総合点にはまとめなかった。例えば、答えの列挙が長い問題を、列挙の長さだけで難問と判定しないためである。

実験の実行コードは `scripts/experiment-certified-difficult-problem-generation.mts` に置いた。全候補と測定値は `artifacts/benchmarks/certified-difficult-problem-generation-20260901.json` に保存した。

## 第1回の結果

直接構造を合成した候補は11問だった。内訳は次の通りである。

- 二階漸化式と有理角の有限状態問題: 7問
- Pell 方程式の解の列と二階漸化式の積状態問題: 1問
- Pell 方程式の解の列を三角関数のべき和の添字へ使う問題: 1問
- 二階漸化式を三角関数のべき和の添字へ使う問題: 1問
- 一次分数変換で多項式の根を移す問題: 1問

11問すべてが、厳密計算、独立検算、全親問題への依存、証明経路の合流、条件の必要性を満たした。単純な逆再生と判定された候補は0問、未使用条件が残った候補も0問だった。

証明段数が最も多かった候補は、問題34から得た Pell 方程式の整数軌道と、問題89から得た三角関数のべき和を合成した問題だった。証明は10段階で、10種類の表現変換を使用した。

## 生成した代表問題

Pell 方程式

\[
x^2-3y^2=1
\]

の正の解を

\[
x_k+y_k\sqrt3=(2+\sqrt3)^k
\qquad(k=1,2,3,\ldots)
\]

で定める。実数 \(\theta\) が

\[
\sin\theta+\cos\theta=\frac1{2027}
\]

を満たすとき、

\[
\sin^{x_k}\theta+\cos^{x_k}\theta>\frac1{2027}
\]

となる正の整数 \(k\) をすべて求めよ。

答えは

\[
k=1
\]

である。

この問題では、Pell 方程式の解の列が \(2,7,26,\ldots\) という添字を作る。一方、\(X=\sin\theta\)、\(Y=\cos\theta\) とおくと、\(X^m+Y^m\) は二階漸化式で厳密に計算できる。二つの経路は「整数軌道が、べき和の添字を選ぶ」という位置で初めて合流する。したがって、どちらか一方の親問題だけでは生成問題の結論に到達できない。

## 第1回で見つかった問題

数学的検証は通ったが、出力には次の欠点があった。

1. 係数1を省略せず、`1a_{k+1}` と表示する場合があった。
2. 高校生向けの解答で、説明なしに「Newton和」という用語を使用していた。
3. Pell 方程式の解の更新を「Pell単数を掛ける」とだけ書き、何を比較したかが不明瞭だった。
4. 上界で一括処理できる \(m=7\) を、巨大な有理数として直接計算していた。

## 改善

係数1を省略する数式整形を追加した。べき和の漸化式は、\(X,Y\) が同じ二次方程式の解であることから一行ずつ導く形へ変更した。Pell 方程式の解の更新は、\(2+\sqrt3\) を掛けて \(1\) と \(\sqrt3\) の係数を比較する操作を明記した。

さらに、直接計算する項を「奇数用または偶数用の上界をまだ適用できない項」だけに限定した。代表問題では、直接計算が \(m=2,7\) の2項から \(m=2\) の1項へ減った。残りは

\[
|X^m+Y^m|<\frac1{2027}\quad(m\ge7,\ m\text{ は奇数})
\]

および

\[
0<X^m+Y^m<\frac1{2027}\quad(m\ge26,\ m\text{ は偶数})
\]

でまとめて処理する。直接計算で残る比較は

\[
u_2-\frac1{2027}=\frac{2026}{2027}>0
\]

だけになった。

## 第2回の結果

改善後に全4,005組を再実行した。生成候補は11問のままで、11問すべてが生成監査に合格した。代表問題の答えも \(k=1\) のままであり、独立した行列計算による検算も一致した。

したがって、今回の短縮は結論や検証条件を弱めたものではない。不要な有限計算を、証明済みの一括評価へ置き換えたものである。

## 製品経路での第3回試験

問題34と問題89を公開画面から選び、製品APIを通して代表問題を生成した。生成には外部LLMを使わず、MORTRAの型抽出、合成規則、厳密計算、独立検算だけを使用した。APIは問題文、答え \(k=1\)、模範解答、状態図、証明経路、生成監査を一つの生成結果として返した。

最初の画面試験では二つの不具合が見つかった。

1. 「親問題への依存 / 検証済み」という表示に対し、試験側が「親問題への依存」だけとの完全一致を要求し、表示済みの項目を未表示と誤判定していた。
2. 状態図に最小幅520pxが残っており、幅390pxの画面では右側の終端状態が横スクロールの外へ出ていた。

第1点は、見出しと状態を含む実際の表示構造に合わせて検査するよう修正した。第2点は、二状態の図に固定幅を使わず、状態数から表示幅と端点座標を計算する共通配置へ変更した。

修正後の自動画面試験では、1440px幅と390px幅の双方で次を確認した。

- 問題文、親問題への依存、未使用条件0件が表示される。
- 二つの状態点が図の表示領域内に収まる。
- ページ全体に横方向のはみ出しがない。
- ブラウザの実行時エラーが0件である。

生成関連の回帰試験は52件すべて成功し、型検査と本番ビルドも成功した。画面試験の結果と画像は `artifacts/test-results/difficult-problem-generation-ui-20260901` に保存した。

## 考察

今回の実験では、異なる分野の構造を本当に合成した、厳密な解答付き問題を生成できた。代表問題は、Pell 方程式、行列による整数軌道、二次方程式の根のべき和、偶奇別の評価を一つの証明で使用する。親問題の文面を変更しただけの問題ではない。

一方、有限状態問題の一部は、周期が長いために答えの列挙量が増えていた。これは証明の本質的な難しさとは区別する必要がある。今回の代表問題を最上位とした理由は、証明段数だけでなく、異なる二つの数学構造が途中で不可欠に合成されているためである。

今回の実験で確認したのは、検証済みの分野横断問題を自動生成できることである。入試本番での体感難易度は、実際の受験者による正答率や解答時間を別に測定する。

## 第4回: 一つの構造から異なる問いを生成する

第3回までの有限状態生成は、整数漸化式と有理角を合成できても、最終的な問いを「余弦列の最小周期」に固定していた。まず、全4,005組について親組ごとの生成上限を3問から64問へ広げた。この変更だけでは候補は11問のままだった。したがって、11問という結果は実験側の打ち切りではなく、生成器が持つ問いの種類が少ないことによって生じていた。

そこで、有限状態を作る処理と、その状態から何を問うかを分離した。ここでいう観測とは、有限状態から余弦値、正弦値、零点の真偽などを読み取る規則である。同じ整数漸化式と有理角から、次の7種類を生成できるようにした。

1. 余弦列の最小周期と1周期の値
2. 正弦列の最小周期と1周期の値
3. 単位円上の点 \((\cos(a_n\theta),\sin(a_n\theta))\) の最小周期
4. 正弦が0となる添字の完全な合同類
5. 余弦が0となる添字の完全な合同類
6. 単位円上の点が初期位置へ戻る全添字
7. 余弦の正・零・負からなる符号列の最小周期と個数

これらは数値だけを差し替えた問題ではない。例えば、フィボナッチ数列 \(F_n\) と \(\theta=\pi/6\) の組からは、次の別々の結論が得られる。

\[
\sin(F_n\theta)=0
\iff n\equiv0\pmod{12},
\]

\[
\cos(F_n\theta)=0
\iff n\equiv4,8\pmod{12},
\]

また、単位円上の点が最初の点へ戻る \(n>1\) は

\[
n\bmod24\in\{1,2,7,17,23\}
\]

である。余弦の符号列は周期24をもち、1周期中の正・零・負の個数は

\[
(12,4,8)
\]

となる。各結論は、同じ有限状態を使うが、同じ答えの言い換えではない。

## 第4回の結果

90問の全4,005組を再実行した結果、直接構造融合の候補は11問から49問へ増えた。49問の内訳は次の通りである。

- 整数漸化式と有理角の有限状態問題: 45問
- Pell 方程式の解の列と二階漸化式の積状態問題: 1問
- Pell 方程式の解の列を三角関数のべき和の添字へ使う問題: 1問
- 二階漸化式を三角関数のべき和の添字へ使う問題: 1問
- 一次分数変換で多項式の根を移す問題: 1問

生成された49問は、構造識別子が49種類、正規化後の問題文も49種類だった。質問形式は11種類だった。49問すべてが、厳密計算、独立検算、全親問題への依存、二つの証明経路の合流、未使用条件0件という生成監査を通過した。

製品画面では、融合生成1回につき最大7問を受け取り、結果欄の前後ボタンで切り替えるようにした。1問だけを表示する画面構造は維持し、複数候補を縦に並べて読みにくくしない設計とした。

製品経路の自動画面試験では、フィボナッチ数列と有理角の親問題を選び、1440px幅と390px幅の双方で7問を生成した。7問の表示内容はすべて異なり、末尾で次ボタンが無効になり、前ボタンで先頭へ戻ることを確認した。ページ全体の横方向のはみ出しと実行時エラーはいずれも0件だった。長い厳密解は隣の解説欄へ重ならないよう、解答欄の内部だけを横に送れる表示へ変更した。生成・監査の回帰試験54件と本番ビルドも成功した。

第4回で増えた38問は、有限状態という一つの共通表現から複数の問いを作った結果である。現時点では増加が有限状態分野へ集中している。次に問題数を増やすには、Pell 軌道、べき和、一次分数変換についても、同じように状態構成と質問形式を分離する必要がある。

## 結論

MORTRA は、現在の90問から、単純な逆再生ではない直接構造融合問題を49問生成した。全49問に厳密な答えと独立検算があり、二つの親問題をともに使用し、未使用条件はなかった。問題文と構造識別子はいずれも49種類で、質問形式は11種類だった。

最も深い候補では、Pell 方程式の整数軌道と三角関数のべき和を合成した。試行後に解答生成規則を修正し、直接計算を2項から1項へ減らした。さらに、有限状態の構成と問いを分離し、一つの親組から最大7種類の証明目標を生成できるようにした。したがって、今回の実験は、問題を一度生成して終わる処理ではなく、生成物の不足を再利用可能な生成規則へ戻す反復になった。

# MORTRA 入力忠実性・公開UI閉ループ検証（2026-09-02）

## 目的

`mortra.ai` に一問または二問を直接入力したとき、入力を別問題へ置き換えず、MORTRA自身の厳密計算で問題文・解答・説明・図・証明書を公開UIへ返せるかを確かめる。直ちに閉じない問題については誤答を公開せず、永続研究キューへ移し、再読み込み後も同じ探索へ戻れることを確認する。

## 仮説

問題28が公開経路で未解決になった原因は解法の不足ではなく、名前を付けない積分式と、TeX数式を閉じる `$` を上界証明の入力形式として認識できていないことにある。この仮説が正しければ、入力形式の一般的な正規化だけで問題28が新たに認証され、固定90問中の他89問の判定は変化しない。

公開UIから長時間ワーカーへ移された二階漸化式のディリクレ級数については、探索量ではなく、問いの「ディリクレ級数」が型付き目標にならず、漸化式の右辺へ吸収されていたことを第二の仮説とした。これが正しければ、問題固有の分岐ではなく、`二階漸化式 -> 一般項 -> ディリクレ変換 -> 収束域` という共通変換を追加することで、係数を変えた数列にも同じ実装が使える。

## 方法

1. `全問題.tex` 由来の固定90問を、期待解答なし、外部LLMなし、独立再生可能な証明書必須の条件で測定した。
2. 名前付き積分 `I=...` と、問題文のままの `\int...<2 を示せ` を同じ型付き積分義務へ変換した。
3. 被積分関数、積分区間、要求された上界を入力から読み直し、異なる被積分関数や上界 `<3` には同じ証明を流用できない回帰試験を置いた。
4. Vercel本番配置後、`https://mortra.ai/ja` の実際の入力欄をPlaywrightで操作した。390 x 844 と 1440 x 1000 の画面で、入力往復、API経路、問題文、解答、解説、証明書、図、横方向のはみ出し、文字化け、再読み込み後の再接続を検査した。
5. 長時間ワーカー `d385135a-6f1b-48d6-b55d-55c27fd3874c` の保存状態を調べた。ラウンド2、深さ7までに1,059状態と213目標を検査していたが、48義務が開いたままで、公開問題は0件だった。保存された診断は、問いが実行可能な観測量を指定していないことを停止理由としていた。
6. 自然文の問いに `DirichletSeries` という型を与え、漸化式の右辺を「のディリクレ級数」の直前で閉じた。厳密実行側には、特性多項式、初期値係数、一般項、ディリクレ変換、収束域を順に計算・再生する共通経路を追加した。
7. 元の係数とは異なる増大型、すべての特性根が単位円内にある減衰型、未対応の重根型を試した。未対応型では一般項だけを返して別の問いへすり替えないことも確認した。
8. UI検査には、ページ全体だけでなく問題文・答え・解説の各欄の内部幅を測る検査を追加した。これにより長い答えの欠けを検出し、数式と結論を別行へ分けた。

積分入力の実装コミットは `09b7757`、ディリクレ級数と欄内検査の実装コミットは `393d083` である。

### 二階漸化式のディリクレ級数

入力 `a_0=2, a_1=3, a_{n+2}=4a_{n+1}-3a_n` から、特性根と初期値を厳密計算して

\[
a_n=\frac{3^n+3}{2}
\]

を得た。任意の固定した複素数 `s` に対して `a_n/n^s` は0へ収束しないため、ディリクレ級数は全複素平面で発散する。係数を変えて最大特性根を3から2へ変えた試験では、証明書の支配根も2へ変化した。特性根を `1/2, 1/3` とした試験では、結果は二つの多重対数関数の和となり、全複素平面で絶対収束した。したがって、固定解答の再生ではなく現在入力から再計算している。

重根 `1` の未対応例はHTTP 422となり、一般項だけを返してディリクレ級数へ答えたことにはしなかった。現在の認証範囲は、相異なる二特性根を持ち、唯一の支配根が単位円外にある場合、または全特性根が単位円内にある場合である。単位円上、重根、同絶対値の複数支配根は今後の共通拡張対象である。

## 考察

修正前は、同じ積分でも `I=...` と名前を付けた形だけが証明核へ届き、元の問題文にある `<2$ を示せ` はTeX閉じ記号のため拒否されていた。数学的能力が消えたのではなく、公開入力と実行可能義務の間で指示対象が正規化されていなかった。入力形式を一つの型付き義務へまとめた結果、固定母集団で問題28だけが増えたため、今回の1問増加には因果的な説明がある。

ディリクレ級数も同様に、長時間探索が少ないのではなく、問いの型が `Scalar` のままで、探索終端が定義されていなかった。観測量の型と共通変換を追加すると、同じ公開入力が永続キュー移送から即時認証へ変わった。係数変異と減衰例でも結果が追随し、重根例は棄却されたため、問題文IDや特定数値を覚えた分岐ではない。

一方、19/90という固定一問ベンチマークは任意問題の完成を意味しない。公開UIで7件が解けた事実と、画像OCRが存在しない事実、71件の固定未解決を分けて扱う必要がある。未解決問題を赤字だけで終わらせず永続キューへ渡す経路は動作したが、キューが最終証明へ到達する能力は別に継続測定する。

## 結論

日本語・TeXで入力する一問解答、図解、二問融合、厳密証明書の公開表示は、本番のモバイル8/8件、デスクトップ8/8件で再現した。問題28は入力形式の修正により固定90問でも新規に認証され、ディリクレ級数は共通変換の追加により公開UIで未回答から認証へ変わった。画像・PDFの文字認識はまだ公開機能ではない。次の実装対象は、単位円上・重根を含むディリクレ変換、残る未解決義務の共通構造、画像を同じ型付き意味IRへ入れる非LLMの入力経路である。

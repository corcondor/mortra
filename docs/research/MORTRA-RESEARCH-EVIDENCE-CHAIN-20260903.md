# MORTRA 研究証拠記録の実装と検証

## 結論

MORTRA の即時生成と長時間探索に、入力、生成物、証明、実行証明書、独立再検証、未解決義務を一つに結ぶ証拠記録を実装した。

生成物の数学的内容または証明書が変わると、再検証結果は一致しない。再検証に失敗した候補は問題データベースへ保存されず、未解決義務として次の探索ラウンドへ戻る。

この変更は、解ける問題の種類を直接増やすものではない。今後の理論修正を、どの入力、生成プログラム、失敗義務に対する修正だったか追跡できる状態にする変更である。

## 問題

実装前にも、次の要素は個別に存在していた。

1. AutonomousSearchState は、探索深さ、未解決義務、次回実行時刻を保存していた。
2. 型付き実行器は、厳密計算と親問題ごとの反事実検査を実行していた。
3. 各問題カードは、証明手順と実行証明書を保持していた。

しかし、これらを同じ入力に対する同じ研究ラウンドとして結ぶ共通の記録はなかった。問題カードだけを書き換えた場合や、生成プログラムと証明書の対応が崩れた場合に、保存処理そのものが拒否する共通境界もなかった。

## 仮説

各研究ラウンドをハッシュで結び、保存直前に別の関数で再計算すれば、次の二つを同時に満たせると考えた。

1. 証明済み候補だけを公開経路へ渡せる。
2. 未解決候補は捨てず、次の理論修正に必要な義務として継承できる。

ここでハッシュとは、内容から計算する 64 桁の識別値である。内容が一文字でも変われば、原則として別の値になる。

## 方法

### 1. 正規化したハッシュ

オブジェクトのキー順に依存しない JSON 表現を作り、SHA-256 を計算する。配列の順序は数学的な入力順序として保持する。

### 2. 問題カード単位の再検証

各候補について、次を検査する。

- 親問題の識別子がすべて証明に使われていること
- 必要な証明義務が消費済みであること
- 射の列と証明設計図の射の列が一致すること
- 厳密計算と独立検査が成功していること
- 登録済み完成経路の再生ではないこと
- 入力問題のハッシュが実行証明書と一致すること
- 生成プログラムまたは厳密解答のハッシュが実行証明書と一致すること
- 問題文、答え、解答、図、証明手順を含む生成物全体が保存時の内容と一致すること

### 3. 研究ラウンド単位の証拠記録

各ラウンドは次を保持する。

- 全親問題の出典ハッシュ
- 受理候補数と拒否候補数
- 各候補の生成物、証明、実行証明書のハッシュ
- 未解決義務と探索前線のハッシュ
- 直前ラウンドの証拠記録ハッシュ

直前ラウンドのハッシュを含めるため、長時間探索の履歴は順番を保った鎖になる。

### 4. 公開経路への接続

同じ処理を次の二経路へ接続した。

- mortra.ai の即時融合生成
- データベースに状態を保存して再開する長時間探索ワーカー

公開画面の解答カードには、問題カード単位の再検証ハッシュを表示する。長時間探索中の画面には、証拠記録の状態を表示する。

## 結果

### 自動検査

合計 34 件の関連検査がすべて成功した。

| 検査集合 | 成功数 / 総数 | 対象 |
|---|---:|---|
| 新しい証拠記録検査 | 7 / 7 | 正常封印、別実行環境、改変拒否、履歴継承 |
| 自律探索検査 | 17 / 17 | 未見一問、複数親、探索再開、登録済み経路拒否 |
| 公開生成検査 | 2 / 2 | 公開経路での未登録融合 |
| 厳密解答検査 | 8 / 8 | 三次方程式、積分、和と極限、失敗診断 |

本番サイトの TypeScript 型検査は成功した。長時間探索ワーカーの本番ビルドも成功した。

### 改変検査

生成プログラムの内容だけを変更し、証明書のハッシュを変更しなかった場合、候補は拒否された。拒否候補数は 1 件、保存候補数は 0 件になった。探索状態は終了せず、証明書再検証の不一致が未解決義務へ追加された。

封印後の解答本文を変更した場合、生成物ハッシュの不一致を検出した。親問題に後から既知の答えを追加した場合、親問題の出典ハッシュの不一致を検出した。

### 公開画面

ローカルの公開画面へ、未登録の連立一次方程式を二問入力した。

- 生成数: 1 問
- 証拠記録の状態: certified
- 受理した問題カード: 1 件
- 拒否した問題カード: 0 件
- 問題カードの証拠記録ハッシュと研究ラウンドのハッシュ: 一致
- 画面に表示した証明書ハッシュと再検証結果: 一致

デスクトップ表示は 1440 × 1000 ピクセルで確認した。携帯表示は 390 × 844 ピクセルで確認した。携帯表示に横方向のはみ出しはなかった。内容を持つ開発用エラー画面もなかった。

画面取得時に WebGL の画素読み出しに関する性能警告が記録された。これは背景描画の画面取得に伴う警告であり、生成処理または表示処理の失敗ではない。

## 考察

実装前は、探索状態、問題カード、実行証明書が別々に正しくても、それらが同じ研究実行に属することを一つの検査で示せなかった。今回の証拠記録により、保存された正答と、次回へ持ち越す未解決義務が同じ入力履歴に結び付いた。

この記録は、今後の自律改善に必要な比較単位になる。次の理論修正では、単に正答数だけを比べるのではなく、どの未解決義務が消え、どの生成プログラムが新しく成立し、どの親問題に対する依存を保ったかを比較できる。

## 次の実験

次は、固定した未見問題群に対して証拠記録を連続生成する。未解決義務を十二個の共通操作へ分類し、同じ義務を複数問で解消する理論修正だけを候補にする。修正前後で、追加正答数、再検証成功率、未解決義務数、追加した共通操作数を比較する。

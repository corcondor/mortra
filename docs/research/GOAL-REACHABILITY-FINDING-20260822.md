# 未解決46問は探索の問題ではない。到達可能性の問題である

`data/goal-reachability-analysis.json`（`python scripts/analyze_goal_reachability.py` で再生成）

## 所見

HAGeo heldout remaining52、6ラウンド×64試行、総試行3,328を全件走査した。

```
                    ゴールに触れた試行あり
  解けた   6問              6/6
  未解決  46問              0/46
  例外                      0件
```

**未解決46問は、64試行すべてで `goal_deduction_count == 0` だった。**
2,750から121,538回の演繹を行いながら、そのどれ一つもゴールに触れていない。

## これで否定された仮説

| 仮説 | 反証 |
|---|---|
| 探索予算が足りない | 未解決の方が閉包が大きい。最大値の中央値 15,746 対 10,847 |
| 補助構成の選び方が悪い | 64通りすべて相異なる path で、全部ゴールに触れない |
| 残差 `ar_residual_l1` を勾配に使えばよい | 残差が動く18問すべてで、ゴールに触れた試行は0 |
| pass@k を上げれば届く | 残差5問に128試行×8ラウンドで solved 0 |

**残差は勾配ではない。** 残差0は解けた結果であって、そこへ至る道ではない。
未解決側は残差が 2.0 から 8.0 の間で動いているが、ゴールには一度も触れていない。
残差を下げる探索を作っても、ゴールに近づかないものを最適化することになる。

この点は 2026-08-22 の初期分析で「検証済みの勾配」と書いたが、誤りだった。
解けた6問で残差0だったのは、解けたから0になったのであって、逆ではない。

## 何が起きているか

閉包は止まっていない。大量に演繹している。だが演繹の方向がゴールと交わらない。

`2023SAGFp8` は 121,538 回演繹してゴールに触れていない。
一方 `2006G4` は 7,928 回で解けている。**量ではなく向きの問題である。**

前向き閉包はゴールを知らずに飽和するまで走る。
`deductions_for_goal` が空のまま `all_deductions` だけが増える。

## 記録の欠落

`worker/backend/yuclid_native_verifier.py` は Yuclid の `payload` に
`all_deductions` と `deductions_for_goal` を受け取っているが、
run artifact に保存しているのは**件数だけ**である。

```python
all_deduction_count=len(all_deductions)
goal_deduction_count=len(goal_deductions)
```

したがって「閉包が何を産んで、ゴールが何を要求していたか」は
既存 artifact からは復元できない。実行時には手元にあって、捨てている。

## 次の実験

**閉包が産んだ述語集合と、ゴールが要求する述語集合の差を名指しする。**

1. `yuclid_native_verifier` に、`all_deductions` の述語名と引数sortの
   多重集合を記録する経路を足す。件数だけでなく分布を残す。
2. ゴール述語から後ろ向きに1〜2段展開し、必要な述語集合を出す。
3. 前向きが産んだ集合と、後ろ向きが要求する集合の差集合を取る。
   これが「今の規則集合で作れないもの」の名前になる。
4. 閉包が小さい問題（`2022CHNSouthEastMOg11p6` 4,484、`2008CTSTp4` 4,786、
   `2002CTSTp25` 4,998）から始める。早く飽和する＝差集合が読みやすい。

差集合が特定の述語族に集中していれば、足すべき規則が決まる。
散っていれば、規則ではなく補助構成の語彙が足りない。**どちらかが分かる。**

## この所見が意味すること

6論文統合で追加正答が0だったのは、実装の質の問題ではない。
型付き交換も sheaf 協調も LEAP 探索制御も、**すべて「ゴールに触れる演繹が存在する」
ことを前提にした改善**であり、その前提が46問すべてで成立していなかった。

順位付けを変えても、通信を減らしても、枝を刈っても、
到達可能な経路が存在しなければ正答は増えない。

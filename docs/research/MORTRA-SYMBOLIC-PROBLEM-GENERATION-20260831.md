# MORTRA 記号的作問と証明逆追跡

## 目的

MORTRA が問題を解くために蓄積した射、証明器、証明書を、未知の問題を生成する機構へ接続する。親問題の証明を単純に逆再生するのではなく、複数の親問題から新しい問いを構成し、必要最小限の条件、厳密な解答、証明、図を一体として生成することを目標とする。

## 先行研究

### AlphaGeometry

AlphaGeometry は、無作為に作った幾何条件から記号推論を実行し、到達した結論を証明依存グラフから逆追跡する。逆追跡によって、結論に必要な最小の前提集合と証明部分グラフを抽出する。この組を新しい定理と証明として使用する。

論文は、合成定理生成に必要な構成要素として、数学対象と定義の実装、前提の標本化、記号推論器、証明の逆追跡を挙げている。公式実装の `trace_back.py` には、不要な前提の削除と補助構成の分離が実装されている。

- 論文: https://www.nature.com/articles/s41586-023-06747-5
- 公式実装: https://github.com/google-deepmind/alphageometry

### SDE-GPG

SDE-GPG は、指定された知識項目を幾何定義へ対応付け、記号推論で候補を生成し、条件検査を通過した候補から問題文、図、段階的な解答を作る。

候補検査では、最短の証明経路、全条件の使用、指定知識項目の使用、証明長と難易度の整合性を確認する。したがって、条件を生成しただけで公開せず、証明に使われない条件を除外する点が重要である。

- 論文: https://aclanthology.org/2025.acl-industry.97.pdf
- 公式実装: https://github.com/tianyangzhang123/SDE-GPG-ACL25

### LeanNavigator と DExplorer

LeanNavigator は、Lean の証明状態を頂点、証明操作を辺とする状態遷移グラフを探索し、新しい定理と機械検証済み証明を生成する。DExplorer も Lean による検証を保ったまま、定理文、証明、探索履歴を生成する。

DExplorer は大規模言語モデルを使用するため、MORTRA の実行経路には採用しない。検証器が生成を制御する閉ループだけを比較対象とする。

- LeanNavigator: https://arxiv.org/abs/2503.04772
- DExplorer 公式実装: https://github.com/Purewhite2019/dexploration_main

## 単純な逆再生で作問できる範囲

証明が

\[
P_1,\ldots,P_k\vdash Q
\]

という形なら、$P_1,\ldots,P_k$ を条件として $Q$ を問う問題は作れる。この意味では、証明の逆再生は作問の一部になる。

ただし、親問題の証明をそのまま逆再生するだけでは、次の問題が残る。

1. 親問題と同じ問いを再掲する可能性がある。
2. 証明に使わない条件が残る可能性がある。
3. 複数の親問題を選んでも、実際には一方しか使わない可能性がある。
4. 正しさは保証できても、新規性、自然さ、難易度は保証できない。
5. 補助構成と初期条件を分離しないと、問題文が不自然になる。

したがって、MORTRA では逆再生を最終処理として使わない。先に新しい証明グラフを合成し、その後で最終目標から必要な前提だけを逆追跡する。

## これまでの射と問題解法の役割

これまでの作業には、作問に必要な四つの役割がある。

1. 射は、数学構造を変換する有限の生成語彙になる。
2. 問題を解く過程は、どの射の合成が真であるかを示す証明グラフを作る。
3. 証明書は、生成した問題の答えと証明を独立に再生できるようにする。
4. 図の構成履歴は、問題文と解答に対応する図を同じ数学対象から生成できるようにする。

したがって、問題解法は作問と別の作業ではない。解法から得た再利用可能な射と証明部分グラフが、作問探索空間の基底になる。

## MORTRA へ実装した閉ループ

現在の公開候補は次の順序で生成する。

1. 各親問題から型付き端点を抽出する。
2. 端点型に適合する合成規則を選ぶ。
3. 異なる親問題の途中構造を結ぶ。
4. 新しい問い、厳密解、証明経路、図を構成する。
5. 問いから証明グラフを逆追跡し、使用した親問題を特定する。
6. 全条件の使用、全親問題への依存、交差合成を検査する。
7. 別の計算経路で証明書を再生する。
8. 親問題の再掲または単純な逆再生と判定した候補を除外する。

実装箇所は次の通りである。

- 型付き端点と合成規則の選択: `lib/mortra/certified-fusion-planner.ts`
- 証明グラフの逆追跡と公開判定: `lib/mortra/certified-problem-generation-audit.ts`
- 公開候補の登録経路: `lib/mortra/certified-fusion-registry.ts`
- 90問全組合せの測定: `scripts/benchmark-certified-fusion-corpus.mts`

この経路では大規模言語モデルを使用しない。問題番号、期待解答、問題固有の固定文型による分岐も使用しない。

## 結果

`全問題.tex` の90問から成る相異なる2問の全4,005組を測定した。80問には検証済み解答と証明書を対応付けた。

- 生成できた組: 116組 / 4,005組
- 親問題の構造を直接合成した組: 11組 / 4,005組
- 検証済みの厳密解を共通構造へ合成した組: 105組 / 4,005組
- 生成監査に合格: 116組 / 116組
- 単純な逆再生と判定: 0組 / 116組
- 厳密計算と独立検証に合格: 116組 / 116組

全結果は `artifacts/benchmarks/certified-fusion-fullproblems-20260831-generation-audit.json` に保存した。

## 考察

この実験は、これまでの射と証明書が作問に利用できることを示した。特に、二階整数漸化式と有理角を有限状態へ変換する一つの規則が、7問の親問題との新しい融合を生んだ。

一方、現在の監査が保証するのは、厳密な可解性、二つの親問題への依存、証明経路の存在、親問題文との差である。人間が感じる独創性、文章の自然さ、入試問題としての価値はまだ保証しない。

105組の証明済み解答合成は、同じ二階漸化式形式を共有する。この105組は正しいが、形式の多様性が低い。したがって、件数だけを作問性能として扱わない。

## 次の実験

次の実験では、既存の証明グラフから問いだけを変えるのではなく、複数の証明部分グラフを途中で合成する。

評価条件は次の通りとする。

1. 証明書付きの新しい結論を生成できる。
2. 逆追跡後の前提がすべて証明に使われる。
3. どの親問題を除いても同じ結論を証明できない。
4. 既存問題と生成済み問題の型付き正規形が重複しない。
5. 問題文、厳密解、証明、図を同じ証明グラフから再生できる。
6. 一つの合成規則が複数の未見問題族で再利用できる。

## 結論

作問を扱う先行研究は存在する。MORTRA に必要なのは、親問題の証明をそのまま逆再生する処理ではない。射で新しい証明グラフを合成し、最終目標から必要最小限の前提を逆追跡し、厳密検証後に問題文、解答、図として表現する処理である。

これまでの問題解法は、そのための生成語彙、証明グラフ、証明書を作っていた。今回、その資産を製品の融合生成経路へ接続した。

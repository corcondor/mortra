# 三次曲線・円・有理角六角形の公開経路

## 目的

公開画面 `mortra.ai/ja` に未登録の問題を直接入力したとき、三次曲線と円の六交点からできる六角形について、問題文、厳密解、証明、図を外部 LLM なしで返せるようにする。

## 修正前の結果

対象問題を本番 API へ送ると HTTP 422 となり、厳密に検証できる解答を返せなかった。定理核には関連する代数操作があったが、一般の日本語入力をその核へ接続する型付きの入口がなく、公開経路から到達できていなかった。

## 原理

円の半径を \(R\)、三次関数を \(y=ax^3+bx\) とする。相似変換

\[
x=Ru,\qquad y=Rv
\]

により問題を単位円へ正規化する。六交点が円周上に並ぶ順序と、各内角が同じ分母をもつ有理角であるという条件から、分母 \(q<5\) を有限に除外できる。残る場合を、交点に対応する単位複素数を根にもつ自己反転六次式へ移し、Vieta の関係と円分体内の厳密計算で係数を定める。最後に得られた六点を元の半径へ戻し、円上にあること、三次曲線上にあること、相異なること、巡回順序、内角をすべて厳密に再生する。

この処理は問題番号、既知の答え、保存済み完成経路を参照しない。入力から抽出するのは、変数名、関数名、円の半径、角度の分子記号と分母記号、および構造条件である。

## 実装

- `math_os_prototype/structural_theorem_query.py`
  - 日本語と LaTeX から構造条件を抽出する。
  - 半径と変数名を正規化し、同じ定理核で処理する。
  - 問題固有の構造が一つでも欠けた入力は受理しない。
  - 厳密解、七段階の証明、六交点を含む平面図を生成する。
- `math_os_prototype/test_structural_theorem_query.py`
  - 元問題、半径変更、変数名変更、日本語の語順変更、LaTeX 表記変更、構造を壊した反例を検査する。
- `tests/test_public_solve.py`
  - 公開 API と同じ経路で元問題と未見変形を検査する。

## 結果

- 構造定理の対象試験: 5/5 成功。
- 公開 solve の対象試験: 3/3 成功。
- 構造定理の全回帰試験: 98/98 成功。
- 公開 solve の全回帰試験: 111/111 成功。
- 製品ビルド: 成功。62 個の Python モジュールと 17 個の画面・API 経路を構築。
- 本番 API: HTTP 200。\(q=5\) と厳密な \(f(x)\) を返した。
- 本番画面: 解答、図、証明を表示。文字化け 0 文字。
- 未見変形: 円を \(u^2+v^2=4\)、関数を \(v=g(u)\)、角度記号を \(a_i/r\) に変更しても、\(r=5\) と対応する厳密な \(g(u)\) を返した。

## 考察

失敗の原因は定理そのものの欠如ではなく、自然文から既存の代数核へ至る接続の欠如だった。今回の修正は一つの問題文を保存するものではなく、同じ構造をもつ入力を相似変換と記号変更の下で同一視する。そのため、表層の数字や文字を変えただけの回帰試験ではなく、正規化後の構造と証明義務が一致するかを検査している。

一方、この結果だけで任意の数学問題を扱えるとはいえない。証明された範囲は「原点を通る奇三次曲線、中心円、相異なる六交点、巡回順序、有理内角」という構造である。次の作問実験では、問題文の相異ではなく、親構造、証明 DAG、使用した射の列の相異を数える必要がある。

## 結論

公開経路の未接続は解消され、元問題と構造を保った未見変形の双方で、問題文から厳密解、証明、図まで同じ再利用可能な変換が完走した。実装コミットは `7ffc0e3` である。

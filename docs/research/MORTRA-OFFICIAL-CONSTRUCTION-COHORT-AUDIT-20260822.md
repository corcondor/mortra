## 目的

問題別の解法分岐を増やさず、Newclid の公式 JGEX 作図意味論を MORTRA の共通な厳密制約へ
一度だけ実装したとき、同じ構造を含む未見問題へ転移するかを測る。対象は、既知点を共有する
2円から別の交点を作る構造を含む HAGeo 固定問題である。

## 仮説

JGEX の作図語彙、点の順序、交点の選択、非退化条件を多項式制約へ保存すれば、表層文型や
問題名に依存せず、同じ作図構造を持つ問題へ適用できる。ただし、作図の elaboration が成功する
ことと、最終ゴールの厳密証明が閉じることは分けて評価する。

## 原理

### 対象コホート

表層正規表現では37問だったが、公式 Newclid parser の構文木で

1. 出力点が1個
2. `on_circle` がちょうど2個
3. 2円が同一の既知点を半径点として共有

を検査すると36問だった。`2021GOWACAp4` は `a1` を `a` と誤認した正規表現の偽陽性であり、
対象から除外した。

### 公式作図意味論

- `iso_triangle a b c` は第1点 `a` を頂点とし、`cong a b a c` を満たす。
- `segment p q` は独立な自由点2個を導入する。
- 既知点を共有する2円の別交点は、Newclid の既存点除外規則に従って既知根を除去する。

二等辺三角形はユークリッド変換で

```text
a = (0,h),  b = (-s,0),  c = (s,0),  s != 0, h != 0
```

へ正規化できる。自由線分が最初の図形なら

```text
p = (0,0),  q = (t,0),  t != 0
```

へ正規化できる。ただし、既存図形の後に現れる線分にはこのゲージを再利用せず、2点の
4自由座標を保持する。同様に、既存図形の後に現れる二等辺三角形は、頂点2座標、底辺中点
2座標、半底辺尺度1変数を保持し、位置と向きを固定しない。これらは特定問題の数値を固定する
ものではなく、合同・共線・垂直・共円などユークリッド不変な証明義務に対する座標ゲージである。

## 実装方法

- `scripts/extract_hageo_known_root_circle_cohort.py`
  - 公式 parser で対象を抽出し、重い Newclid runtime を短命プロセスへ分離する。
- `scripts/benchmark_hageo_known_root_circle_cohort.py`
  - 問題ごとの独立実行、時間打切り、checkpoint、証明書監査を行う。
- `worker/backend/jgex_exact_constraint_bridge.py`
  - 既知根を持つ2円の厳密 deflation、`iso_triangle`、`segment` の公式意味を実装した。
- `scripts/update_hageo_capability_union.py`
  - 証明ファイルのハッシュ、最終余り0、厳密再生を監査し、固定89問の集合和を更新する。

評価では外部 LLM、期待解答、補助句を使っていない。問題ID、年度、期待値による分岐もない。
各問60秒で完了しない場合は誤答ではなく right-censored timeout とした。

今回の結果は、共有既知根を持つ2円の意味論欠落が実際に得点を失わせていたことを支持する。

## 2026-08-23 継続実験: 停止点の保存と相似チャート

### 目的

300秒で時間打切りとなった28問について、停止した演算を保存し、その演算を数学構造に沿って
縮約したときに追加正答が生じるかを測った。

### 方法

1. elaboration、局所消去、Groebner、非退化飽和、証明書再生のcheckpointを追加した。
2. 既知根を持つ2円の第2交点で、全既存点との巨大な距離式を毎回因数分解する処理を廃止した。
   同じ円対・同じ既知根の二重生成は構造キーで拒否する。無関係な既存点との一致を許すことは
   JGEXの定義域を広げる側なので、この広い領域での証明は元の非退化領域でも成立する。
3. 後続構成または相似目標へ渡る第2交点は、巨大な明示座標ではなく2本の一次関係で保持した。
4. Newclidの `simtri` / `simtrir` を公式対応順に従って実装した。2つの実残差の平方和ではなく、
   複素座標上の1本のGaussian-rational多項式として表し、次数増加を避けた。
5. 第2交点の6座標だけを消去変数とし、元の図形の座標は厳密係数として扱った。証明書は
   多項式係数ごとに再生し、余り0だけでは採用しなかった。

問題ID、年度、期待解答による分岐は追加していない。外部LLMとデータセット補助句も不使用である。

### 失敗した中間実装

- 全ての第2交点を関係表現にすると、既存の `2022CHNSouthEastMOg11p6` が飽和で遅くなった。
- 相似の2条件を平方和にすると余り0には到達したが、証明書再生が180秒を超えた。
- 依存グラフ上の全中間点を消去変数にすると12変数のままだった。第2交点6座標へ限定した。
- 6並列ではCPU競合により、単独57.08秒で証明できる `2006G9` も120秒で右打切りとなった。
  この右打切りを不正解とは数えず、単独の再生済み証明書を採用した。

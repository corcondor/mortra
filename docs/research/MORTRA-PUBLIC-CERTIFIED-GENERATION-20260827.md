# MORTRA 公開版の検証付き作問核

## 目的

公開サイトで、保存済み問題を検索するのではなく、入力された二つの親問題から新しい問題をその場で構成し、問題文・図式・模範解答・検証証明書まで返せるかを確認する。

今回の製品条件は次の通りとした。

1. 外部LLMを使用しない。
2. 問題IDや期待解答による分岐を持たない。
3. 二つの親問題を別々の入力として保持する。
4. 片方を除くと成果物を再構成できないことを検査する。
5. 同じ答えを二つの独立した厳密計算で再現する。
6. 検証できない入力は、古い問題の再利用や長時間キューへの偽装で埋めない。

## 仮説

作問を文章生成として扱わず、可逆な数学的変換として扱えば、親問題への依存性、新規性、答えの正しさを同じ証明成果物で検査できる。

最初の公開チャートには、次数2〜4の一変数モニック整数多項式の根配置を採用した。二つの親多項式を `f,g`、根を `alpha_i,beta_j` とし、次の三つを構成する。

```text
root_sum:        alpha_i + beta_j
root_product:    alpha_i * beta_j
root_difference: alpha_i - beta_j
```

根配置の二項演算は二つの入力を本質的に使い、出力は再びモニック整数多項式になるため、型が閉じる。

## 方法

### 1. 親問題のelaboration

日本語またはLaTeXから等式を取り出し、次数2〜4の一変数モニック整数多項式へ変換する。文章中の `text` と `operatorname` は数式変数として数えない。係数・変数名・次数は問題IDに依存せず解析する。一次式は二項演算が片親の恒等変換になりうるため、全親依存性を保つ公開経路では受理しない。

### 2. 第一の計算経路

各親多項式のNewton和をBigIntで厳密に求める。二項定理を使って出力根の冪和へ写し、Newtonの恒等式を逆向きに適用して出力多項式を復元する。

### 3. 独立検証

同じ出力をSylvester行列の整数行列式、すなわち終結式から独立に構成する。二つの係数列が完全一致した候補だけを公開する。

### 4. 親依存性

出力の型付き導出には二つの親ID、根配置、二項演算、Newton和、終結式照合を保存する。全親依存性検査に合格しない候補は返さない。

### 5. 製品UI

- A欄だけ: 既存の型付き厳密解答器で問題を解き、必要に応じて関数グラフなどの図を返す。
- A/B欄: 二つの親から新しい融合問題を作り、問題文、構造図式、答え、解答、検証経路を返す。
- 公開作問チャートが入力を扱えない場合: 生成済み問題を使い回さず、現在の対応範囲を明示する。

## 考察

### 現時点で作問できるか

できる。ただし、公開版で自動作問を実証した範囲は一変数モニック整数多項式の根構造である。任意の自然文二問、任意の幾何二問、整数と図形の任意融合を生成できるとはまだ言えない。

今回の重要点は、198件が保存問題の検索や係数だけの置換ではなく、入力係数から毎回出力係数を再計算し、別経路で検算されていることである。変数名変更では証明構造が保たれ、係数変更では答えが再計算される回帰も通過した。

### まだ足りないもの

1. 任意の自然文を実行可能な型付きIRへ落とすelaborationの被覆率。
2. 幾何、整数、確率、微積分で、入力型から出力型へ戻る可逆な作問チャート。
3. 非幾何分野の独立した凍結ベンチマークと証明書監査。
4. 幾何融合で、問題文・補助図・模範解答を同じ構成DAGから出す公開経路。
5. 長時間探索を再開可能にするジョブleaseと、進捗・停止理由の永続化。

### 少ない表現で他分野へ広げる順序

語彙を問題ごとに増やさない。未対応入力を、停止した型付き義務で分類し、一つのチャートが複数問題を閉じる場合だけ追加する。

```text
多項式根配置
  -> 漸化式 / 行列 / 特性多項式
  -> 代数と微積分のパラメータ問題

付値・合同・整除
  -> 整数方程式 / 格子 / 整数図形

アフィン座標・二次形式・円束
  -> 平面幾何 / 3次元断面 / 軌跡

有限状態・遷移行列
  -> 確率 / 数列 / 組合せ
```

各拡張は、親保持、可逆性、独立検証、全親依存性、未見splitを同時に測る。

## 結論

公開版に、外部LLMを使わず二つの親問題から新しい問題・図式・模範解答・二重検証証明書を返す最初の作問核を実装した。198/198件で生成と二経路検証に成功し、非対応入力12対の誤受理は0だった。

これは任意作問の完成ではない。製品として使える厳密な最小核が初めて閉じた段階である。次は同じ検査規約を保ったまま、漸化式・行列、付値・合同、アフィン幾何、有限状態へチャートを増やす。

## 追試: `全問題.tex` 90問の全組合せ（2026-08-31）

### 目的

公開用の固定例ではなく、`全問題.tex` の90問から作る全4,005組を対象にし、次の三点を区別して測る。

1. 問題文の構造だけから新しい問題を作れる組。
2. 二つの保存済み証明から厳密解を取り出し、共通の証明構成へ合成できる組。
3. どちらもできず、研究探索を継続すべき組。

総数だけでは、構造を発見したのか、既知の厳密解を再利用したのかが分からない。このため、1を「構造融合」、2を「証明合成」として別集計にした。

### 仮説

一方の親が数学対象、他方の親がその対象に作用する可逆変換を与える場合、問題固有の解法を追加せず、次の共通チャートで融合できる。

```text
多項式の根配置
  -> 可逆な一次分数変換
  -> 変換後の根配置
  -> 分母消去による整数係数多項式
  -> 有理関数の固定点方程式
  -> 逆代入恒等式による完全性検証
```

この仮説が解法暗記でないための必要条件として、問題ID変更、親の入力順交換、係数変更、片親除去を試験する。

### 方法

1. 90問を一度だけ読み、4,005組を漏れなく列挙した。
2. 構造融合の判定では、親IDと問題文だけを渡した。保存済み解答と証明は渡していない。
3. 証明合成では、検証済み証明書がある親だけを別経路で処理した。
4. 新しいチャートでは、BigInt多項式演算により逆変換を代入し、分母を払って変換後の根の多項式を構成した。
5. 独立検証では、`(cx+d)^d P(T(x)) = +/- det(T)^d f(x)` を係数ごとに照合した。
6. 片親を除いたときに構成不能となることを型付き入力ポートで確認した。
7. 実APIと公開UIで17番・18番を選択し、問題文、答え、射図、解答、証明経路、証明書まで表示した。

### 誤受理の監査

旧来の広い正規表現では、整数らしい語を含む問題と三角形らしい語を含む問題を350組「対応可能」と数えられた。しかし、確率・相関の条件を捨てて整数問題として扱う例を含み、親問題の特徴的な構造を保存していなかった。この350組は汎化ではなく誤接続なので、結果から除外した。

### 考察

今回の1組増加は、問題17と18の専用解法を登録した結果ではない。根配置という対象と一次分数変換という作用を別々に型付けし、可逆な座標移送として合成した結果である。係数変更後も再計算できるため、少なくともこのチャートの被覆範囲では解答の暗記ではない。

一方、任意の二問を融合できる状態ではない。直接構造融合は4/4,005に留まり、問題文だけから抽出できた構造端点も90問中5問である。現在の主要な不足は探索深度より、自然文から再利用可能な対象・作用・不変量を取り出すelaborationと、型の異なる端点を閉じる可逆チャートの被覆である。

105組の証明合成も検証済みの新問題ではあるが、親問題の内部構造を直接融合した4組とは性質が異なる。公開UIではそれぞれ「構造融合」「証明合成」と表示し、同じ能力として見せない。

### 結論

`全問題.tex` の実問題から、保存解答を使わずに新しい構造融合を1組追加し、直接構造融合を3組から4組へ増やした。メビウス変換と多項式根配置のチャートは、ID変更、入力順交換、係数変更、親除去に対して期待どおりに振る舞った。

これは任意作問の完成ではない。次に増やすべきものは問題別規則ではなく、同じ監査を通る対象・作用チャートである。候補は、漸化式と行列、付値と合同、アフィン二次形式と円、有限状態と遷移行列である。

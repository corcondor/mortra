# MORTRA: 型付き証明義務に条件付けた逆向き信用割当実験

実施日: 2026-08-21

## 1. 目的

過去に終端証明へ寄与した補助構成へ信用を戻すだけでは、現在の問題と無関係な
構成まで優先される。本実験では、履歴上の信用を真理値に使わず、現在の未解決な
型付き証明義務へ直接接続し、さらに同じ義務を厳密証明器が実際に閉じた場合だけ
探索上の信用として昇格させる。

検証する仮説は次である。

> 終端信用を現在の型付き義務との単一化と、候補追加後の新規native事実による
> 同一義務の閉鎖に条件付ければ、射名の暗記を避けつつ探索順位を改善できる。

## 2. 原理

証明状態を `S`、その未解決型付き義務を `O(S)`、候補構成を `c` とする。
候補をJGEXの厳密な構成定義へ展開して得る事後条件集合を `P(c)`、開発集合で得た
終端信用を `q(c)` とする。

### 2.1 型付き直接照合

```text
U(c,S) = { o in O(S) | exists p in P(c), typed_unify(p,o) }
```

述語名だけでなく、引数、対称性、既知点、型付き穴を単一化する。信用候補スロットへ
入る必要条件は `q(c) > 0` かつ `U(c,S)` が空でないことである。

### 2.2 因果的な閉鎖確認

候補追加前のnative事実を `F(S)`、追加後を `F(T_c(S))` とし、新規事実だけを

```text
DeltaF(c,S) = F(T_c(S)) minus F(S)
```

とする。信用を検証済みにする条件は、単一化した義務と、新規事実で閉じた義務が
同じことである。

```text
V(c,S) = 1  iff  U(c,S) intersect Closed(DeltaF(c,S)) != empty
```

したがって、別の義務が偶然閉じた場合、候補追加前から既知だった事実、射名だけの
類似は信用にならない。最終的な正しさは従来通りYuclid native証明書の再生だけで
決め、信用は有限候補の順序制御にしか使わない。

### 2.3 有限探索

後向き推論はOR分岐である。従来の順位上位24件だけを残すと、穴のないground枝が
型付き証人を持つ枝を押し出した。そこで上限24を維持したまま25%を証人枝へ予約し、
ground枝3本ごとに証人枝1本を混ぜた。候補検証は4本、信用枠は最大1本である。
無制限グラフや問題別規則は追加していない。

## 3. 根拠

この制御は三つの既存原理に対応する。

1. **論理プログラミングの単一化**: 規則の結論と現在のgoalが型付きで単一化できる
   ときだけ、その規則を後向き候補にする。
2. **CEGISの反例・検証ループ**: 候補は提案にすぎず、実行後の検証器が仕様を満たす
   と確認したときだけ採用する。
3. **信用割当**: 終端成功の履歴は探索priorとして使えるが、現在状態への適合と局所的
   な実証なしに真理や得点へ変換してはならない。

本実験の新しい科学的争点は、履歴信用の大きさではなく、現在の義務を実際に閉じた
という局所的証明進捗が未見問題の経路選択へ追加情報を与えるかである。

## 4. 実装

- `CandidatePolicySpec.obligation_conditioned_credit` を追加。
- 構成の厳密postconditionと開いた `Atom` を対称性込みで単一化。
- 正の信用かつ直接照合を持つ候補だけを1枠へ予約。
- Yuclid再生前後の事実差分を取り、同一義務の閉鎖だけを `verified` とした。
- `closed_parent_obligations` と `new_native_facts` を全候補traceへ保存。
- OR分岐を平坦化せず、固定予算内で証人穴を持つ枝を保存。

## 5. 方法

### 5.1 単一問題スモーク

- 問題: `2020IranGOAp2`
- `N=1`, `K=1`, 候補検証4本
- 固定seed 31
- 外部LLM、期待解、問題ID分岐、dataset補助節は不使用

### 5.2 固定未見10問の対照実験

同一の10問、seed、候補数、native verifier、時間条件を用いた。

- 対照群: `residual-portfolio`
- 処置群: `obligation-credit-mixed`
- 差分: 処置群だけが固定済み信用台帳から最大1本の候補を追加
- 真理面: 両群ともYuclid native証明書再生のみ

## 6. 結果

### 6.1 単一問題

17個の未解決義務中14個が型付き穴を持った。正の履歴信用3候補のうち、現在の義務へ
直接単一化した候補は1個だった。

```text
reflect(t,o1,p)->d
  matches cong(?D,o1,o1,t), cong(?B,o1,o1,t)
```

候補追加後の新規native事実だけを使っても、この二義務は閉じた。したがって局所信用
の厳密ゲートは実データ上で発火した。ただし問題全体は未解決だった。

### 6.2 固定未見10問

| 指標 | 対照群 | 処置群 |
|---|---:|---:|
| 完了 | 10/10 | 10/10 |
| 正解 | 0/10 | 0/10 |
| 型付き穴を持つ義務 | 50 | 50 |
| 正の信用候補 | 0 | 27 |
| 現在義務へ直接照合 | 0 | 3 |
| 信用枠で検証 | 0 | 2 |
| 同一義務を新規事実で閉鎖 | 0 | 2 |
| 選択候補が閉じた義務の合計 | 7 | 7 |
| 最終未解決義務の合計 | 202 | 202 |
| 対照群と異なる選択経路 | - | 0/10 |
| 壁時計時間 | 115.66秒 | 148.66秒 |

処置群は28.54%遅かった。厳密信用が成立した2候補は次である。

- `2008CTSTp4`: `reflect(d,e,c)->g` が `cong(?A,?B,d,e)` を閉鎖。ただし最終選択外。
- `2011G3`: `reflect(k1,m,e)->g` が `cong(?A,?B,k1,m)` を閉鎖し、選択された。

## 7. 考察

### 支持されたこと

- 射名の信用だけでなく、現在の型付き義務への直接接続を機械的に判定できた。
- 候補追加前後の差分を取り、同じ義務のnative閉鎖だけへ信用を限定できた。
- ground枝だけに偏る有限frontierを修正し、証人穴を持つOR枝を失わず扱えた。
- 問題固有の解法や数値を追加せず、同一の単一化・差分検証を複数問題へ適用した。

### 支持されなかったこと

- `N=1, K=1` の固定10問では追加正解は0だった。
- 選択経路は対照群と全く同じで、最終残差も改善しなかった。
- 信用候補の追加検証により実時間は増えた。

原因は、信用が誤っているからではなく、この小予算では残差frontierが既に同じ候補を
含み、局所的な一義務の閉鎖が終端goalまで届かないためである。この結果から得点向上を
主張してはならない。

## 8. 結論

「射名への信用」から「現在の型付き義務へ単一化し、候補追加後の新規native事実が
同じ義務を閉じた場合だけ信用する」制御へ置き換えた。これは解法暗記を抑える厳密な
安全条件として成立した。

一方、固定未見10問では正解、経路、最終残差を改善せず、28.54%の時間増となった。
したがって本実験が示したのは得点向上ではなく、信用割当を論理的に正しくする基盤で
ある。次の反証可能な実験は、検証済み局所閉鎖を次ラウンドのproof DAGへ保持する
`N=2,3` 増分実験である。そこで追加正解または残差減少が出なければ、この信用priorは
探索制御として棄却する。

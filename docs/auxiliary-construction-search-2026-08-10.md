# 補助構成探索と正答率停滞の根本原因（2026-08-10）

## 結論

従来のMathOSが接続していたのは、AlphaGeometry 2のうち**形式化済み前提を閉包して
目標を検査するDDAR論理核**だけだった。公式テストの `problems_with_aux` は、言語モデルが
発見した補助点をあらかじめ問題へ追加した集合であり、DDAR単体の26/26は補助点発見能力を
意味しない。

そのため、これまでの「AlphaGeometry相当まで到達」という表現は不正確だった。正確には
「形式化後・補助点供給後のsymbolic backendを再現」までである。

## 今回追加した実行経路

LLMを使わず、次の閉ループを追加した。

```text
AG2形式問題
  -> DDAR閉包
  -> 未証明なら有限の型付き補助構成を列挙
  -> 数値座標で退化候補を除外
  -> 各候補を前提へ追加してDDARを再実行
  -> 目標gapと導出閉包の増加でbeam選択
  -> 元の目標を厳密に証明できた候補だけ採用
```

構成文法は次の9射である。

- 2直線の交点
- 点を通る平行線と直線の交点
- 点を通る垂線と直線の交点
- 直線と円の交点
- 中点
- 垂足
- 点対称移動
- 正三角形の第三頂点
- 外心

各層で使う点は、目標への出現と前提出現頻度で選ぶ最大8点に制限する。探索は深さ、beam幅、
試行回数で有限になり、各試行の構成種、入力点、目標gap、閉包サイズ、採否を
`attempt_trace`として返す。問題ID、期待解、解答文、LLMは入力しない。

## 反暗記テスト

三角形の2本の高さから3本目の垂直性を示す形式問題を使った。

| 条件 | 結果 |
|---|---:|
| 補助構成探索なし | 未証明 |
| 有限文法探索あり | 1試行、深さ1で証明 |
| 回転・平行移動・一様拡大した4同型問題 | 全て同じ `line_intersection` 射で証明 |
| 同じ前提に対する偽の平行目標 | 32候補を試して未証明を維持 |

発見した補助点は、辺 `AC` と既知の高さ `BD` の交点である。座標値を覚えた処理ではなく、
4点から2直線を作り、その交点を新しい点として追加する同じ射が発火した。

Workerの対象3テストは成功し、TypeScript buildも成功した。既存Worker全79テストも、
補助探索の基本版追加後に成功している。

## なぜ3,574問の正答率が急増しないか

固定3,574問の最新記録は734正解（20.54%）、回答精度67.46%である。失敗層は次の通り。

- `morphism_to_backend_gap`: 2,266問
- `semantic_or_strategy_error`: 350問
- `elaboration_or_type_gap`: 108問
- `backend_execution_gap`: 89問

MATH 700問中、geometry分類は32問だけで、3正解、2誤答、27問が
`morphism_to_backend_gap`だった。仮に残り29問を全て正解しても、3,574問全体への寄与は
最大29/3,574 = 0.81ポイントである。

さらに公開ベンチ入力は自然文・TeX・Asymptoteであり、今回の探索器はAG2形式IRを入力とする。
したがって、正答率停滞の根本原因は補助構成語彙だけではない。

1. 自然文・TeX・図からAG2述語へloweringする経路が未接続。
2. 補助構成探索器がWorkerの単体backendに留まり、3,574問のPython評価経路へ未接続。
3. 現在の画素再観測は円の非空・切れ・対称性を検査する描画QAであり、画素から補助線を
   発見する視覚推論ではない。
4. 全体の2,266問は算数、代数、確率、整数などを含み、幾何backendだけでは覆えない。

## 次の受理条件

1. 図付き自然文から `Point/Line/Circle + coll/perp/para/cong/cyclic + goal` を作る。
2. 数値図は仮説生成だけに使い、前提の真偽を画素から勝手に追加しない。
3. 補助構成前に未証明、構成後に厳密証明、という差分を必ず残す。
4. 相似変換、点名変更、作図の表示範囲変更でも同じ構成射列になることを測る。
5. MATH geometry 32問を独立スライスとして測り、その後に固定3,574問を再測定する。

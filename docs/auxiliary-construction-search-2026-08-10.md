# 補助構成探索と正答率停滞の根本原因（2026-08-10）

## 結論

従来のMathOSが接続していたのは、AlphaGeometry 2のうち**形式化済み前提を閉包して
目標を検査するDDAR論理核**だけだった。公式テストの `problems_with_aux` は、言語モデルが
発見した補助点をあらかじめ問題へ追加した集合であり、DDAR単体の26/26は補助点発見能力を
意味しない。

そのため、これまでの「AlphaGeometry相当まで到達」という表現は不正確だった。正確には
「形式化後・補助点供給後のsymbolic backendを再現」までである。

## 今回追加した実行経路

LLMを使わず、次の閉ループを追加した。

```text
AG2形式問題
  -> DDAR閉包
  -> 未証明なら有限の型付き補助構成を列挙
  -> 数値座標で退化候補を除外
  -> 各候補を前提へ追加してDDARを再実行
  -> 目標gapと導出閉包の増加でbeam選択
  -> 元の目標を厳密に証明できた候補だけ採用
```

構成文法は次の9射である。

- 2直線の交点
- 点を通る平行線と直線の交点
- 点を通る垂線と直線の交点
- 直線と円の交点
- 中点
- 垂足
- 点対称移動
- 正三角形の第三頂点
- 外心

各層で使う点は、目標への出現と前提出現頻度で選ぶ最大8点に制限する。探索は深さ、beam幅、
試行回数で有限になり、各試行の構成種、入力点、目標gap、閉包サイズ、採否を
`attempt_trace`として返す。問題ID、期待解、解答文、LLMは入力しない。

## 反暗記テスト

三角形の2本の高さから3本目の垂直性を示す形式問題を使った。

| 条件 | 結果 |
|---|---:|
| 補助構成探索なし | 未証明 |
| 有限文法探索あり | 1試行、深さ1で証明 |
| 回転・平行移動・一様拡大した4同型問題 | 全て同じ `line_intersection` 射で証明 |
| 同じ前提に対する偽の平行目標 | 32候補を試して未証明を維持 |

発見した補助点は、辺 `AC` と既知の高さ `BD` の交点である。座標値を覚えた処理ではなく、
4点から2直線を作り、その交点を新しい点として追加する同じ射が発火した。

Workerの対象3テストは成功し、TypeScript buildも成功した。既存Worker全79テストも、
補助探索の基本版追加後に成功している。

## なぜ3,574問の正答率が急増しないか

固定3,574問の最新記録は734正解（20.54%）、回答精度67.46%である。失敗層は次の通り。

- `morphism_to_backend_gap`: 2,266問
- `semantic_or_strategy_error`: 350問
- `elaboration_or_type_gap`: 108問
- `backend_execution_gap`: 89問

MATH 700問中、geometry分類は32問だけで、3正解、2誤答、27問が
`morphism_to_backend_gap`だった。仮に残り29問を全て正解しても、3,574問全体への寄与は
最大29/3,574 = 0.81ポイントである。

さらに公開ベンチ入力は自然文・TeX・Asymptoteであり、今回の探索器はAG2形式IRを入力とする。
したがって、正答率停滞の根本原因は補助構成語彙だけではない。

1. 自然文・TeX・図からAG2述語へloweringする経路が未接続。
2. 補助構成探索器がWorkerの単体backendに留まり、3,574問のPython評価経路へ未接続。
3. 現在の画素再観測は円の非空・切れ・対称性を検査する描画QAであり、画素から補助線を
   発見する視覚推論ではない。
4. 全体の2,266問は算数、代数、確率、整数などを含み、幾何backendだけでは覆えない。

## 次の受理条件

1. 図付き自然文から `Point/Line/Circle + coll/perp/para/cong/cyclic + goal` を作る。
2. 数値図は仮説生成だけに使い、前提の真偽を画素から勝手に追加しない。
3. 補助構成前に未証明、構成後に厳密証明、という差分を必ず残す。
4. 相似変換、点名変更、作図の表示範囲変更でも同じ構成射列になることを測る。
5. MATH geometry 32問を独立スライスとして測り、その後に固定3,574問を再測定する。

## 2026-08-10 追加実装: AG2型パイプライン

前節で未接続だった自然文/TeX loweringを、次の一本の実行経路として追加した。

```text
日本語/英語/TeX
  -> 有限の幾何字句・関係構文解析
  -> TypedPredicate IR
  -> 非線形最小二乗による非退化な数値図構成
  -> AG2 formal problem
  -> S1/S2/S3 analysis
  -> 6種類の有限探索木
  -> 9種類の型付き補助構成
  -> DDAR exact verification
```

### S1/S2/S3の音性境界

- `S1`: 元の前提だけからDDARが導出した事実。
- `S2`: 目標も一時的に仮定したときに増える事実。
- `S3`: 数値図では成立するが未証明の事実。

`S2/S3` は候補点と構成射の順位付けにしか使わない。DDARへ渡す前提は、元の前提と
明示的に構成した補助点の定義だけである。数値図が目標を満たしても証明済みとは扱わない。

探索木は `classic / incidence / metric / circle / deep_narrow / shallow_wide` の6分布である。
これはAG2のSKESTと同じ「異なる探索分布を併用する」という契約を有限文法で再構成した
もので、Google内部のGemini proposerをコピーしたものではない。

### 実測

| 検査 | 結果 |
|---|---:|
| 公式AG2 DDAR回帰 | 26/26 |
| Worker全回帰 | 85/85 |
| 自然文/TeX・補助構成・漏洩防止の対象検査 | 9/9 |
| 和文TeXと英文の表層変換 | 同一goal・同一`line_intersection` |
| 根拠なしの数値的に実現可能な目標 | 未証明を維持 |
| 未対応の重心述語 | 黙って削除せず`unformalized` |

公式26問は形式化済みで、うち11問は補助点が手動供給済みである。したがって26/26を
AG2論文のIMO-AG-50 42/50と比較してはいけない。現状は、自然文を含む独自の小さい
metamorphic検査を通した段階であり、IMO-AG-50自然文44問の再現値ではない。

### 現在の不足

形式化語彙は `coll/perp/para/cong/cyclic/eqangle` と中点・外心の展開までである。
重心、接線、円と直線上の所属、比、角定数、画像OCRからの図形対応はまだ同じIRへ
完全loweringできない。未対応語を捨てる代わりに棄却するため音性は保つが、coverageは低い。
次の評価単位は、未見の自然文幾何問題について `formalization rate / proved rate / false-proof rate`
を別々に測ることである。

## 2026-08-10 第2反復: 実行語彙と構成射の拡張

DDARが既に持つがMathOSから使えていなかった述語を、自然文形式化層へ接続した。

| 表層概念 | lowering先 |
|---|---|
| 線分比 `AB/CD=k` | `rconst` |
| 比の等式 `AB:CD=EF:GH` | `eqratio` |
| 角定数 `∠ABC=60°` | `s_angle` |
| 距離の加法関係 | `distseq` |
| 直線/線分上、交点 | `coll` の合成 |
| 円周上 | `cyclic` |
| 接線（接点・中心が明示） | 半径と接線の `perp` |
| 垂心 | 2本の高さ `perp` |
| 内心 | 2本の角二等分 `eqangle` |
| 重心 | 中点、共線、2:1、距離加法の5述語 |

重心のhidden midpointは入力ごとに新しい型付き点として導入する。専用の「重心問題解法」は
存在せず、下流は `coll/cong/rconst/distseq` のみを見る。

補助構成文法には次の2射を追加し、合計11射とした。

- `Segment × Ratio -> Point`: 問題中の整数比から内分点を構成。
- `Angle -> BisectorRayPoint`: 3点から内角二等分線上の点を構成。

英語形式化では、従来 `[A-Z]` にcase-insensitive検索を適用していたため、
`the orthocenter` の文字を点 `t,h,e` と誤認する欠陥が見つかった。点名を大文字字句へ
厳格化し、日本語/英語の表層差が同じ述語骨格へ落ちることを回帰検査した。

数値図の受理誤差もDDARの `ATOM=1e-12` に合わせ、最小二乗後にLM法で再収束し、
17桁で座標を渡す。近似的に共線だがDDARでは偽となる図は `backend_rejected` になる。

### 第2反復の実測

- Worker全回帰: 90/90。
- 自然文/TeX/音性の対象検査: 14/14。
- 公式形式化済みDDAR回帰: 26/26。
- 比を満たす数値図だけを生成した反例: DDARでは未証明を維持。
- 未対応の傍心: 表層条件を捨てず `unformalized`。
- 同一点を端点に持つ垂線・比・角: 型検査で実行前に棄却。

次の未接続は、傍心、接点や中心が省略された一般接線、名前付き円の同一性、複数文字の
点名、画像上のラベル対応である。これらは語句追加だけでなく、存在点の導入と指示対象解決を
必要とする。

## 2026-08-10 第3反復: 円の談話対象と画像ラベルgrounding

円を文字列ではなく次の型付き談話対象として保持する層を追加した。

```text
CircleObject(name, center?, through_points, source_span)
  -> anaphora resolution (Γ / その円 / this circle)
  -> membership / tangent elaboration
  -> coll / cong / cyclic / perp
  -> numerical witness
  -> DDAR
```

`Oを中心としAを通る円Γ` の後に `その円` が現れた場合、同じCircleObjectへ束縛する。
接点が明記されない接線では、新しい接点を存在変数として作り、直線上、円周上、半径との
垂直性を同時に課す。外接円の中心が省略された場合も、3点から定まる等距離点を存在変数と
して導入する。これは接線問題の解法テンプレートではなく、円と接線の定義のelaborationである。

画像については、生成モデルOCRを使わない `DiagramGrounding` を追加した。本文IRから期待される
点名を有限集合として受け取り、画像中の文字候補をテンプレート照合し、Hough線分の端点・交点へ
束縛する。出力には文字位置、対応点、距離、信頼度、未解決ラベルを残す。合成三角形に対する
元画像、ノイズ付加、1.2倍拡大の3条件でA/B/Cを全てgroundできた。これは任意フォントOCRや
画像だけからの定理理解ではなく、本文と図の指示対象を接続する最小の実行可能段階である。

対象回帰は19/19、Worker全回帰は95/95、公式形式化済みDDAR回帰は26/26。名前付き円の
和文・英文は同じ `cong + perp` 骨格へ落ち、接点省略時にはhidden contactが実際のAG2形式
問題へ現れる。全経路の `uses_language_model` はfalseである。

## 表現チャネル評価の理論仕様

「AIに最も伝わる言語」は媒体だけでは決まらない。意味 `M`、表現器 `E`、受信系 `D`、
検証器 `V` を固定し、次の多目的損失で比較する。

```text
J(E,D) = task_error(D(E(M)), M)
       + lambda * encoded_length(E(M))
       + mu     * inference_compute
       + nu     * ambiguity_or_decode_failure
       + xi     * verification_cost(V, D(E(M)))
```

自然言語、記号圧縮、音声、図、型付きIR、機械語を、同じ数学タスクの意味同値なチャートとして
比較する。圧縮率だけではなく、正答率、校正、摂動耐性、実行時間、証明器受理率を測る。
MathOSの仮説は、単一の万能言語ではなく、意図は自然言語、空間関係は図、意味は型付きIR、
計算はCAS命令、保証は証明certificateという層別プロトコルがPareto最適になる、である。

## 第4反復: SKEST共有workspaceの実体化

従来の `finite_SKEST_style_ensemble` は複数の探索木を順に実行していたが、失敗ノードから得た
事実を次の木へ渡していなかった。したがって「shared S1/S2/S3 analysis」という説明は、論文の
SKESTにある動的知識共有を実装したものではなかった。

今回、全探索木が参照する `shared_workspace` を追加した。共有可能なのは、DDARが厳密に証明した
元問題の点だけからなる述語である。目標そのものと、生成した補助点を含む事実は除外する。
各試行は新たに共有した事実を `shared_facts_added` に残し、後続木は共有事実に現れる点を候補生成で
優先する。これにより、classic木で得た中間事実をdeep-narrow木が再利用するというSKESTの契約を、
LLMなしの有限探索で実行できる。

検証は対象3/3、TypeScript build成功、公式公開DDAR例26/26。なお公式26例中11例は補助点が入力済みで、
Google内部のGemini proposerは公開されていない。したがって本実装はDDARと共有workspaceの再構成であり、
論文のend-to-end 42/50を再現したという主張ではない。

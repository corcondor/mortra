# Rikyū から MORTRA へ移すべき本質

## 構造の対応

```
Rikyū    一つの依頼 → 一つの創作アイデンティティ → 多数のデザイン成果物
MORTRA   一つの構造 → 一つの検証済み数学状態     → 多数の表現・成果物
```

移すのは見た目ではなく、**成果物を独立に生成しない**という設計。

## MORTRA の成果物

すべて同じ semantic ID を参照する。独立生成を許さない。

```
解答 / 証明 / 別証明
静止図 / 対話図 / 3Dシーン / シミュレーション
LiveProof
記事 / 研究ノート
X カード / Instagram リール / 動画
ワークシート / PDF / スライド
ロボットの軌道
```

実装は `lib/mortra/world/world-types.ts`。
`auditWorld()` が、意味を参照しない成果物・証明書のない `proved`・
不変量を宣言しない射を落とす。

## 「一つを直したら全部更新」

```
「座標解法ではなく幾何的に説明して」
  → 証明経路が変わる
  → affectedByRoute() が作り直す成果物を返す

「高校生向けに」「3Dで」「15秒で」「逆格子から説明して」
  → 意味は変わらない。描画方針だけ変わる
  → affectedByPolicy() が作り直す成果物を返す
```

前者と後者を区別するのが要点。後者を「別々に生成」にすると一貫性が崩れる。

## 素材層の対応

Rikyū が写真・動画の素材ライブラリを持つのに対し、MORTRA は
**意味付きの部品**を持つ。画像アセットではない。

```
三角形 / 円 / 接線 / 円錐曲線 / 多面体
ばね / 振り子 / 剛体 / 波
テンソルノード / Dynkin ノード / Cayley グラフ / Hasse 図 / Feynman 辺
FCC / BCC / HCP / Miller 面 / Brillouin ゾーン
```

型は `lib/mortra/vision/visual-ir.ts` の `VisualNode` に入っている。
どれも `of: SemanticId` を必須にしてあるので、意味に紐づかない部品は作れない。

## 言い方

Rikyū は「もう、デザインしなくていい。」と書いた。機能ではなく、やらなくてよくなることを言った。

MORTRA で同じ位置に来るのは、たとえば次の形。ただし**言い回しは真似しない**。

```
できること（事実として言える）
  入試の言い回しから、LLM なしで図を構成し、証明を閉じ、
  その証明に同期した図を描く

まだ言えないこと
  「東大数学が◯%」  未見問題で測っていない
  「AlphaGeometry より」  比較していない
```

会社名で比べない。評価軸で示す。
